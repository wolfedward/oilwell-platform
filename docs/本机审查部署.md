# 本机审查部署

此工具只安装单机、回环地址的工程审查副本。必须从已提交且干净的发布源码运行；不会接管现有 PostgreSQL/Mosquitto 服务，不会读取或修改原工作目录、冻结演示或既有业务库。安装、启动和恢复需要人工明确执行。请先留足 PostgreSQL 数据、WAL、SQLite、备份和恢复副本的实际磁盘空间；配置中的逻辑容量不是磁盘空间保证。

## 前置条件

- Windows 当前用户对新目标父目录具有创建权限；目标目录必须不存在，不能是链接、用户主目录、工作区或其上级目录。
- 已安装 PostgreSQL 18.6（`C:\Program Files\PostgreSQL\18\bin`）、Mosquitto 2.1.2（`C:\Program Files\Mosquitto`）、Python 3.13.2（`C:\Users\hp\AppData\Local\Programs\Python\Python313\python.exe`）。无需 Windows 服务或管理员提升。
- 发布源码的 `backend`、`frontend`、`server.py`、静态资源（含公开接口资料 30 个文件及 ZIP）、生产依赖和部署工具均已提交且无未提交改动。工具从提交的原始字节导出逐文件哈希清单到新目标 `code`；初始化、迁移、权限检查、启动和备份前的后端操作均在该副本的专用虚拟环境中执行，避免 Windows 工作区换行符与发布字节不一致。启动前逐文件校验。安装会建立独立虚拟环境并安装 `requirements-production.txt` 的固定版本。
- 默认新端口 HTTP `8770`、PostgreSQL `55432`、MQTT `1884` 必须空闲。工具拒绝占用，不结束陌生进程。恢复副本示例另用 `8771`、`55433`、`1885`。

## 安装与运行

在已提交的工作区执行，路径改为准备好的新目录：

```powershell
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy init --target 'C:\Users\hp\AppData\Local\OilWell\review-20261011' --source 'C:\Users\hp\.codex\worktrees\production-device-registry\外专双百'
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy launch --target 'C:\Users\hp\AppData\Local\OilWell\review-20261011'
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy status --target 'C:\Users\hp\AppData\Local\OilWell\review-20261011'
```

只有 `launch` 成功且独立验证通过后访问 `http://127.0.0.1:8770/`。启动最多等待 60 秒，要求实际 HTTP 登录及模块能力、中心 MQTT 订阅成功、波形接收健康记录、回执账号的 MQTT QoS 1 发布确认，以及组装和反演 worker 各自完成一次真实工作循环；仅进程存在或端口占用不算成功。每次启动的逐项结果写入当前用户专有的 `private\readiness-<UUID>.json`，失败时保留供排障。配置文件及代理 ACL 的哈希被封存，修改后启动和状态检查均拒绝；停机仍可针对已记录进程执行。用户名和一次性初始化密码存放在目标的 `private\accounts.json`，仅当前 Windows 用户可读；终端输出、命令行参数和普通日志不包含密码。数据库和 MQTT 凭据在 `private\credentials.json`，不要上传、粘贴到工单或复制到共享目录。目标目录先设置当前用户专有 ACL，再写任何密码。部署标记记录 UUID、目标路径、端口、源码提交及哈希、数据库系统标识和被管理子进程身份。

工具显式创建全新 PostgreSQL 集群、不同的迁移所有者和运行账号。台账先迁移；随后由台账所有者在波形首次迁移前授予固定列投影；波形迁移完成后再运行完整历史授权。所有运行账号不得继承所有者或超级用户权限。新 MQTT 代理仅监听 `127.0.0.1`，账号 ACL 只允许相应上行订阅和回执发布；另有两条仅供审查就绪检测的 `oilfield/review/health/…` 发布权限，不产生业务回执。HTTP、中心接收、回执发布、波形接收/组装/回执发布及反演 worker 均作为该目标的隐藏子进程运行；不启动网关发送、Modbus 轮询或控制下行。

停止和备份：

```powershell
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy stop --target 'C:\Users\hp\AppData\Local\OilWell\review-20261011'
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy backup --target 'C:\Users\hp\AppData\Local\OilWell\review-20261011'
```

`stop` 只对已记录且创建时间、可执行文件、完整命令行均匹配的进程发停机命令；PID 重用或身份不符时拒绝。HTTP 使用其私有停机令牌。备份先确保写入进程均停止，再用 `pg_dump` 自定义格式导出 PostgreSQL，用 SQLite backup API 复制身份库，并记录 SHA-256、源码版本、容量、角色和各业务表行数。备份保留在目标 `backups\<UUID>` 中，受用户专有 ACL 保护；备份完成后集群停机。

恢复只写入另一不存在的目标，不覆盖原目标：

```powershell
& 'C:\Users\hp\Documents\外专双百\.venv\Scripts\python.exe' -B -m tools.review_deploy restore --backup 'C:\Users\hp\AppData\Local\OilWell\review-20261011\backups\<UUID>' --target 'C:\Users\hp\AppData\Local\OilWell\review-restored-20261011' --source 'C:\Users\hp\.codex\worktrees\production-device-registry\外专双百' --http-port 8771 --postgres-port 55433 --mqtt-port 1885
```

恢复先验备份文件哈希与相同源码清单，再创建全新集群和新数据库密码；恢复原身份库及账号，按原角色所有权恢复 PostgreSQL，核对业务表行数和只读权限探针后标记可启动。原目标和原备份均保留。若安装或恢复中断，目标及日志会留在原处供审查；工具不会删除或自动接管不完整目录。纠正后请选择另一全新目标，或人工制定并审查恢复处理步骤。凭据文件和备份同样不得公开。

本机审查副本没有实际设备接入、现场测量真实性、硬件联锁或多主机容灾证明。`control_enabled=false`；工程计算及影子策略不能作为现场控制授权。上线前还须分别验证设备、供电、保护、网络隔离、备份容量和现场操作规程。
