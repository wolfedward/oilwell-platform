# WP-02 生产设备台账、井号时效绑定与点表版本设计

日期：2026-09-23。状态：方案范围已获用户认可；本详细设计待用户审阅，尚未实施。

任务对应：Y1-02（可靠采集与处理）、Y1-03（安全传输与共享）、Y3-05（集成平台）。仅响应年度工作任务，不包含绩效申报目标。

## 1. 已确认的目标与本稿约定

用户已认可：建立独立生产设备台账，复用现有账号权限和界面；支持登记、审核、停用、退役；井号关系按采样时刻解释；点表修改留新版本；变更可审计；保留独立演示版，不删除旧数据、不开放远程启停。

成功标准不是“出现一个台账页面”，而是以下事实可以核对：

- 已登记但从未上报的设备能够查到，状态不会被误报为在线。
- 不同网关下的同名终端不会混为一台设备，未知终端不会自动登记成已启用设备。
- 设备由 A 井迁往 B 井后，迁移前采集、迁移后补传的数据仍属于 A 井。
- 可以查清某时刻平台要求使用哪一版点表；没有终端确认时，明确显示“实际应用版本未确认”。
- 权限不足、并发冲突或审计失败时，不留下半完成的设备/井号/点表变更。

本稿需审阅的实施约定：首版仅支持服务器当前时刻生效，不允许倒填历史绑定或预约迁井；退役标识不复用；迁井使设备转为停用待复核；首版登记状态不等于 Broker 凭据已撤销或现场设备已停机。

## 2. 现状与架构选择

核对基线提交 `38997ed`：

- `backend/services/devices.py` 的设备、场景和通道配置依赖 SQLite 与虚拟终端；不适合作为物理设备登记的事实来源。
- `backend/center/schema.sql` 仅有接收消息、测点及分区，无生产井号和注册关系。
- `backend/center/postgres.py` 以网关/终端组合查询接收链路，但“收到过数据”不是“已登记或经审核”。
- OWP-EDGE/1.0 没有 `point_map_version` 或设备配置应用回执；不能从收到某个点值推断实际配置版本。
- 账号、角色与会话仍在 SQLite。继续复用登录，不在本工作包重做身份系统。

已比较两条路线：扩展旧台账改动较少，但需长期协调虚拟状态与 PostgreSQL 数据；独立生产台账需要新增数据模型，但可把生产关系与其审计放在同一数据库事务。采用后一条路线，不同时迁移全部旧业务。

### 组件边界

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| 生产台账领域服务 | 状态、绑定、点表、变更校验及事务 | Modbus 连接、MQTT 配置下发 |
| PostgreSQL 台账仓储 | 登记关系、时间区间、版本、审计、幂等请求 | 修改已有原始遥测 |
| 生产台账查询服务 | 登记列表、独立链路状态、按测量时间解析来源 | 将结果直接用于自动控制 |
| HTTP 接口 | 现有会话鉴权、权限、输入边界、稳定错误码 | 信任请求正文中的操作者或角色 |
| 生产设备台账页面 | 表单、审批、历史、匹配结果及失败提示 | 伪造在线状态或“已应用”回执 |

代码后续独立组织在 `backend/registry/` 与 `frontend/pages/field-registry.js`，仅在现有启动、路由和权限初始化处做必要接线；避免继续把新业务堆进 `backend/center/postgres.py`。这是结构约定，不是本轮已创建的产品模块。

## 3. 范围与明确不做的事项

本工作包交付：生产井号基础目录、设备登记与生命周期、绑定历史、点表快照及审核/关联、权限与事务内审计、来源核查查询、管理页面、迁移与回退说明。

不做：自动扫描或注册陌生设备、模拟台账批量转正、凭据签发/撤销、配置远程下发、固件升级、波形协议、历史关系纠错重写、远程启停，以及新的诊断/节能算法。

**本阶段为观察核查模式。** MQTT v1 原有接收路径及主题保持不变；格式合格但未登记的数据仍可在原始中心查询中查看，在新台账视图标记未登记/未归属，不自动成为经审核的生产数据。本阶段不增加因台账状态而拒绝 MQTT 消息的逻辑。强制准入须与 WP-03 持久异常隔离配套实现，单独验证后启用。

## 4. 数据所有权与标识

在现有 PostgreSQL 数据库中增加独立 `device_registry` schema。运行代码使用限定 schema 的表名，不依赖可变的 `search_path`。

| 对象 | 核心信息 | 不变量 |
| --- | --- | --- |
| `wells` | UUID、作业区代码、井号代码、名称、active/archived、行版本 | 作业区+井号唯一；代码创建后不可改，不与 SQLite 井号自动等同 |
| `devices` | UUID、gateway_id、device_id、厂家/型号/序列号、接入方式、用途声明、状态、行版本 | 网关+终端永久唯一；退役后不回收；不凭序列号自动合并 |
| `device_state_periods` | 设备、状态、生效区间、关联审计事件 | 同设备状态区间不重叠；查询历史状态不用当前状态代替 |
| `well_bindings` | 绑定 UUID、设备、生产井 UUID、生效区间、操作事件 | 同设备同一时刻至多绑定一口井；同一口井允许多个测量设备 |
| `point_map_versions` | 设备、版本号、父版本、完整规范化快照、摘要、draft/approved/rejected、审核记录 | 内容快照不可覆盖；版本号单调增加；批准/驳回后不可改结论 |
| `point_map_assignments` | 设备、已批准点表版本、生效区间、操作事件 | 同设备期望版本区间不重叠；不代表终端已应用 |
| `audit_events` | 事件 UUID、操作者快照、动作、对象、原因、前后内容、时间、请求标识 | 业务变更与审计同事务；应用角色只能追加/读取，不能改删 |
| `operation_receipts` | 操作者、幂等键、请求摘要、已提交结果 | 同键同请求返回原结果；同键不同请求冲突；不重做业务变更 |
| `registry_head` | 单行递增台账修订号 | 每次成功变更递增，用于分页和核查结果的一致性标识 |

所有实体 UUID 由服务端生成。线上网关/终端/测点沿用 OWP-EDGE/1.0 ASCII 标识规则，大小写敏感。井号代码采用同样规则，中文展示名独立保存；作业区代码用于命名空间，不宣称已经实现多租户或分区数据权限。

绑定通过外键引用生产设备和井号；点表以设备 UUID+版本号唯一，关联使用该复合外键，不能把别台设备的版本关联过来。内容快照及封闭区间通过列权限和数据库触发器禁止覆盖；批准条件仍需在业务事务内校验，不声称普通外键能验证审核状态。索引覆盖设备组合标识、作业区+井号、各时效区间、对象审计时间和幂等作用域。

行版本、点表版本及全局修订号均为正 BIGINT，API 使用十进制字符串传输，`expected_version` 原样回传字符串，避免浏览器整数精度损失；拒绝布尔值、浮点形式、前导零和超限。达到上限时明确报冲突，不回绕复用。

基础文字字段不接受 NUL、孤立代理码点和控制字符；名称/型号/厂家最多 120 个 Unicode 码点，序列号最多 128，操作原因 2—500，人工核查依据最多 1000。禁止密码、私钥、会话令牌和可执行脚本字段，不提供任意附件上传或 URL 抓取。

设备用途为 `commissioning`（联调）或 `production`（生产用途声明），在 pending 状态内可修改并留审计，启用后不可改；用途声明不构成物理来源证明。字段没有默认“真实现场”选项，不从报文 `source` 自动取信。

迁移不会预置生产井或设备。无实物时生产目录可以为空，测试实体只在隔离测试库创建。更换网关、设备替换或线上标识更换须新建登记记录；本版不自动认定为同一物理设备。

## 5. 生命周期与审核

登记状态使用 pending（待审核）、active（已启用）、suspended（停用待复核）、retired（退役）。每次转移携带预期行版本、原因和幂等键。

| 转移 | 条件/效果 |
| --- | --- |
| 新建 → pending | 受权人员登记，不扫描上线，不要求已上报 |
| pending/suspended → active | 有当前井号绑定、当前已批准点表、人工身份/接入核查依据；具备审核权限 |
| active → suspended | 受权人员明确停用；保留绑定和期望点表，历史不变 |
| 非 retired → retired | 审核权限；关闭当前绑定及点表关联，保留全部历史 |
| retired → 其他 | 不允许；误操作需未来专门纠错流程，不能直接改数据库绕过 |

“已启用”仅表示台账审核完成，不等于实物在线、算法可用或获得现场控制权。`active` 不以最近上报作为强制条件，避免设备登记流程反向依赖已接入；页面同时显示“从未上报”或实际链路状态。

非退役设备的元数据（名称、厂家、型号、人工依据）可以受控修改并增加行版本；身份标识和用途锁定规则不变。退役后只读，不允许新绑定、点表或元数据变更。首版不要求额外双人操作：获审核权限的用户可以审核本人登记内容，必须留下真实操作者记录；既有诊断/策略的独立复核规则不因本模块改变。

## 6. 时效绑定与历史归属

统一保存带时区的 UTC 时间，精度到微秒；界面显示北京时间和明确时区。区间采用左闭右开 `[valid_from, valid_to)`，未结束的上界为空。

同设备的绑定、状态和点表关联分别使用 PostgreSQL 排除约束，禁止区间重叠；设备行锁与预期行版本解决并发操作，不依靠“先查没有再插入”。排除约束组合 UUID 等值和时间范围重叠，迁移角色安装 `btree_gist`，应用启动不自动安装扩展。依据：[PostgreSQL 时间范围与排除约束](https://www.postgresql.org/docs/18/rangetypes.html#RANGETYPES-CONSTRAINT)、[btree_gist 支持类型](https://www.postgresql.org/docs/18/btree-gist.html)。

### 本版时间策略

- 变更在服务器当前时刻生效，由数据库在取得变更锁后取一次时间 T，所有关联变化共用 T；请求正文不接受生效时间。
- 不接受补填过去的安装时间来归属既有数据，也不接受预约未来迁井。已封闭区间不能改；开放区间只允许关闭一次，不更换所属井或起点。
- 若服务器时钟回退，导致 T 不晚于要关闭的区间起点，整次变更拒绝并提示时间异常，不伪造未来时间绕过。
- 创建登记之前的旧数据保持未登记历史；存在登记但没有覆盖采样时刻的绑定时显示“未归属”，不套用现在的井号。

### 迁井事务

先验证目标井处于 active、预期设备版本匹配，再原子地关闭旧绑定、创建新绑定、关闭原点表关联并记录审计。原设备 active 时同时转为 suspended；pending/suspended 保持相应状态。需要重新选择已批准点表并人工复核后才能启用，不自动沿用原井配置。

例如在 T=12:00:00 迁井，11:59:59.999999 的数据属于旧井，12:00:00 的数据属于新井；两条数据都在 13:00 到达也不改变这个结果。解绑关闭绑定和期望点表关联，设备 active 时转 suspended；井号有开放绑定时不允许归档。同井重复绑定、重复停用等非状态转移请求返回冲突，已提交请求的同键重试除外。

## 7. 点表版本与应用状态

每次保存完整点表生成新版本，引用父版本；即使是 draft 内容也不覆盖。审核只能将 draft 转为 approved 或 rejected；重新修改/复核要新建版本。批准不是关联，关联不是下发，下发也不是应用确认。

点表首先描述测点代码、单位和可选工程上下限：

- 平台 Modbus 网关：额外保存 unit_id、FC03/04、零基 PDU 地址、数值类型、字节序、字序、scale/offset、poll_group，强制只读。复用现有 PointDefinition 的转换语义，但注册入口须严格拒绝布尔值伪装整数等异常类型。
- 自主 MQTT 终端：只保存上报测点语义与量程，不虚构不存在的 Modbus 寄存器字段。
- 每版 1—256 个唯一测点，整次 JSON 请求不超过 64 KiB；超出任一限制明确拒绝。数值必须有限；量程下界不得大于上界；禁止写功能码与 writable=true。
- 地址空间、寄存器宽度与现有读取器一致；Modbus 03/04 的基础定义参照 [Modbus 官方应用协议](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)。点表不是自动安全认证。

服务端采用 `registry.point-map.canonical.v1` 规则：固定字段、默认值展开、测点按 ASCII 代码排序，整数参数保留整数，scale/offset/量程转有限 binary64；使用 Python `json.dumps(ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False)` 后编码 UTF-8。保存规则名、规范化字节与结构化内容，SHA-256 对保存字节计算，不从 PostgreSQL JSONB 重新序列化求摘要。相同内容可有不同业务版本；摘要用于内容比较，不声称是数字签名或跨语言通用规范。规则将来变更需新规则名，不改旧快照。

关联已批准版本前须存在当前井号绑定，且版本属于该设备、接入方式相符；锁定设备后关闭旧关联并新增区间。若设备 active，同时转 suspended，需人工核查并再次启用；不会更改网关本地文件，也不会向设备发网络请求。

查询同时返回：`expected_map_version`、`reported_map_version`、`application_status`。v1 路径后两者固定为 null / `unverified`；不提供人工勾选“终端已确认”的后门。收到与点表相符的数值也只能显示“已匹配平台期望定义，终端实际版本未确认”。

入库值已是工程量，核查时不能再乘 scale 或叠加 offset。逐项检查测点存在、单位逐字匹配、工程量范围；越限只产生独立核查结果，不改写原样本 value、quality 或 source。

## 8. 事务、审计与并发

所有成功变更在一个 PostgreSQL 事务中完成业务记录、历史区间、审计、幂等回执及全局修订号更新；任何一步失败全部回滚。不要先提交 SQLite 审计再写 PostgreSQL，也不要声称跨两个库已有原子事务。

现有会话鉴权在请求入口完成；服务端复制用户 ID、用户名、展示名、角色和身份域标识（`platform-local`）到审计快照。客户端不得提交 actor 字段覆盖身份；记录请求当时身份，不随以后用户名修改而重写历史。

台账写入频率较低，首版统一先锁 `registry_head`，再锁设备、引用对象并复核条件，锁顺序固定。以数据库约束作为最后防线。每个实体修改必须匹配 `expected_version`，失配返回冲突，不能覆盖他人的修改。

所有写请求必须提供 UUID 幂等键。作用域为身份域+操作者+键，请求摘要包含方法、路由和验证后的正文；权限校验先于数据库访问，包括回执读取。同键同内容返回原已提交结果，同键不同内容返回冲突。数据库连接在提交时中断，客户端保持同一键重试，不盲目生成新键再次登记。重放返回原提交时间/修订号和 replayed 标志，不新增审计或修订号；页面随后读取当前实体，不用旧回执覆盖较新的界面状态。

审计记录必要的前后字段、版本、事件时间和原因，不记录凭据。应用权限禁止改删审计及历史快照；这不是抵御数据库超级用户的密码学防篡改承诺，备份及管理员审计仍属后续运维工作。

## 9. 权限与账户隔离

不复用 MQTT 入库账号执行台账写操作。迁移身份拥有 DDL；台账应用身份只获得此 schema 必要读写权限及只追加审计权限；查询身份仅 SELECT。三者不因方便而获取原始遥测 UPDATE/DELETE 或 Broker 管理权限。

新增显式 `[postgres_registry]` 配置，连接同一中心数据库；凭据只能引用环境变量或 Windows 凭据管理器，不允许内联密码。缺配置时显示“生产台账未配置”，不退回使用入库身份写台账；远程连接遵循已有 verify-full/CA 规则。

启用台账还须显式配置 `[postgres_query]` 专用只读身份并授予新 schema 的 USAGE/SELECT。核验 registry、query、center 的主机、端口和数据库名称一致，拒绝跨库拼接。未启用台账时，旧中心查询的现有配置兼容逻辑不变；开启台账不允许回退复用入库身份。运行用户不得拥有 schema、扩展或相关表，不能靠超级用户连接通过最小权限验证。

| 权限 | 默认授予角色 |
| --- | --- |
| `registry.read` | 管理员、生产工程师、算法工程师、设备运维、复核评审 |
| `registry.devices.manage` | 管理员、设备运维 |
| `registry.wells.manage` | 管理员、生产工程师 |
| `registry.bindings.manage` | 管理员、生产工程师、设备运维 |
| `registry.maps.manage` | 管理员、算法工程师、设备运维 |
| `registry.review` | 管理员、生产工程师、复核评审 |

审核权限控制启用、退役及点表审核；停用允许设备管理或审核权限；其他操作按各自权限检查。完整审计查询还需既有 `audit.read`。原始测点或链路状态查询分别额外要求 `telemetry.read` 或 `acquisition.read`，不借台账接口绕过原权限。

系统管理员获得全部新权限和页面；仍须满足版本、状态和审计规则。版本化权限迁移仅增加本模块权限，不重置现有用户密码或覆盖用户已配置的其他授权。

## 10. 查询与界面

新增“采集监控 → 生产设备台账”，不替换旧虚拟设备管理页。包含井号目录、设备列表/详情、绑定历史、点表版本/审核、核查结果和操作历史。

列表默认以登记为主表，左关联网关+终端接收状态，从未上报的设备也存在。行政状态、链路状态（从未上报/在线/延迟/离线）、期望点表和实际应用状态独立展示。无相应权限的链路区域隐藏且不请求数据；数据库异常显示不可用，不拿联调数据补齐。

新增解析查询在同一个 PostgreSQL 只读 Repeatable Read 事务中读取原始样本与台账区间，用 `measured_at` 匹配井号、当时状态和期望版本。该隔离级别用于保证一次请求内的读取快照一致，不替代写入并发约束。[PostgreSQL 事务隔离说明](https://www.postgresql.org/docs/18/transaction-iso.html)

结果保留原始 message_id、sample_index、测量/接收时间和质量，另附绑定 ID、井 ID、期望点表版本、采样时状态、当前状态以及核查结果。登记/绑定/点表未覆盖、未知点、单位不符、越限分别给出原因；时钟异常和 bad/uncertain 质量不能被台账审核变成合格。本版本的 `eligible_for_automation` 固定 false，匹配结果不等于经过终端配置确认或算法质量验证。

每次响应携带台账修订号及接收截止时间。翻页要求沿用两者；期间台账修订变化返回明确冲突并要求刷新，不让同一列表前后使用不同归属解释。首版不支持跨请求保留旧数据库快照，也不新增批量导出。

时效解析查询须指定完整 gateway_id+device_id 组合，或生产井 UUID（二选一）；可以按传输标识查询尚未登记的链路，结果标记未登记，不要求先创建假的登记记录。单次时间窗最多 31 天、每页最多 200 条，沿用当前接收截止时间的稳定翻页口径。核查页提供组合标识输入，并可从已有接收链路页携带筛选条件进入；登记列表本身不自动收录这些未知终端。

查询时不修改或回填原始遥测表。井号/设备名称是当前展示名，稳定身份与历史归属由不可改的标识及绑定区间确定；名称变更可查审计。原中心 API 字段及行为保持不变；新核查视图不自动接入算法训练、产量统计或自动策略。

## 11. 管理接口与错误边界

独立命名空间 `/api/registry`，所有路径均需鉴权，不放到公开厂家静态资料目录。

| 类别 | 设计接口范围 |
| --- | --- |
| 基础目录 | GET/POST `/wells`；POST `/wells/{id}/changes`（名称或归档） |
| 登记 | GET/POST `/devices`；GET `/devices/{id}`；POST `/devices/{id}/changes`（允许的元数据） |
| 状态 | POST `/devices/{id}/state`，仅接受上述合法状态转移；GET `/devices/{id}/state-history` |
| 绑定 | GET/POST `/devices/{id}/bindings`；POST `/devices/{id}/unbind` |
| 点表 | GET/POST `/devices/{id}/point-maps`；POST `/devices/{id}/point-maps/{version}/review`；GET `/devices/{id}/point-map-assignments`；POST `/devices/{id}/point-map-assignment` |
| 核查 | GET `/resolved-telemetry`；GET `/devices/{id}/link-status` |
| 审计 | GET `/audit`，支持对象/操作者/时间过滤 |

写请求携带原因、幂等键；涉及已有实体时包含预期行版本，点表审核另带所审核快照摘要，防止审错版本。无 DELETE 接口，不接受正文指定任意 SQL、路径、凭据、远程地址或生效时间。

注册接口使用严格 JSON 读取：64 KiB 上限、UTF-8、重复键/未知字段拒绝、数值有限、标识和 Unicode 检查；不能直接照用现有宽松 `_json_body` 而遗漏重复键。保持其他旧接口行为不变。

列表和历史统一分页，默认每页 20、最多 200、偏移量不超过 100,000；时间筛选必带时区，拒绝反向区间。审计查询默认近 24 小时、最长 31 天。新建成功返回 201，其余成功变更返回 200，响应都包含对象标识、版本和台账修订号。设备/井号创建以外的变更使用行版本控制；点表新建/审核/关联同时推进所属设备行版本，防止并发审核与登记变更互相错过。

状态码：未登录 401、无权 403、对象不存在 404、版本/状态/区间/幂等冲突 409、输入无效 422、配置或数据库不可用 503。返回稳定错误码与可操作的中文说明，不把 SQL 或连接串返回页面。连接超时 3 秒、锁等待 1 秒、语句超时 3 秒；这些是各阶段上限，不宣称是端到端请求总超时。

写接口只接受 application/json；浏览器请求需同源校验，禁止跨源 CORS。会话可复用现有 Cookie/Bearer 机制；有 Origin 时必须匹配配置允许的站点，不以未验证 Host 为唯一依据，无 Origin 的受控 API 客户端须用 Bearer。接口配置未允许公网暴露前继续仅监听本机。

## 12. 部署、兼容与回退

- 迁移以显式工具执行，检查 schema 版本和摘要；应用启动不执行 DDL、不自动建账号、不批量激活旧设备。
- 新 schema 初始为空。保留原 `public.ingest_messages` 与 `public.telemetry_samples`，不追加注册外键阻断既有入库，不修改 MQTT v1。
- 应用启动核验配置、schema 和必要权限；缺失时台账单独不可用，旧中心查询/采集和演示功能仍可用。执行器不自动降低安全检查来启动。
- 所需数据库迁移/授权若受本机权限限制，交付可审阅的迁移包并报告未部署，不用入库账号提权或宣称已经上线。
- 回退关闭新模块配置和导航，继续旧采集路径；保留新 schema 数据供调查和重启恢复，不以 DROP TABLE 回退。
- 新模块应保持本地部署限制；其查询只读身份必须随本模块部署落实，正式服务化、异地备份、TLS 现场部署等仍是独立运维工作。

## 13. 验证标准

| 编号 | 要验证的行为 |
| --- | --- |

| R02 | 同网关同终端唯一；跨网关同名可分别登记；并发重复登记仅一条成功 |

| R06 | 并发绑定/迁井/审批由真实数据库约束和版本条件阻止覆盖；多设备同井允许 |
| R07 | 解绑/迁井/退役、点表关联及状态变化在单事务内完成；失败无半条关系 |
