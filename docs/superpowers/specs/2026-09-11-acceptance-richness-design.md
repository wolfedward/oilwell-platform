# 验收演示丰富化设计说明

日期：2026-09-11  
交付时限：75 分钟内形成可正常演示版本

## 目标

在不破坏现有采集、诊断、节能控制、权限和审计闭环的前提下，提升首页与采油监控的信息密度，并将 48 口井的电功图、示功图和诊断数据改造为具有工程差异、坐标完整、前后关联的业务测试数据。

## 设计约束

- 旧 Demo 仅作为页面内容、典型功图轮廓和坐标口径参考，不复制其静态假数据结构。
- 页面不得出现“演示数据”“验收数据”等标记；数据库继续保留 `source_type`、设备标识和生成时间以供技术追溯。
- 不使用 `Math.random` 或浏览器临时拼数。实时波动来自服务端虚拟终端，历史波动来自数据库时序记录。
- 功图不是独立绘制：先定义目标位移—载荷轮廓，再按抽油机机构参数、平衡转矩、传动比和效率反算电机有功功率；现有转换模型再由电功率还原示功图。
- 所有 SVG 趋势图和功图必须展示坐标轴、刻度、网格、轴标题与单位。
- 保持离线可运行，不新增外部依赖，不改变 127.0.0.1 的监听范围。

## 交付范围

### 1. 主页总览

首页补充日产液、日产油、当日耗电、平均泵效、在线率、数据完整率、活动报警、待审批策略等指标；同时展示 14 日产液/耗电双趋势、工况分布、重点异常井、设备与数据质量、最近业务动态和功图入口。页面定时重新读取 `/api/dashboard`，刷新后展示数据库中的最新时点和真实追加数据。

服务端首页读模型增加工况统计、重点井、最近诊断/报警/命令动态、在线率和数据质量率，全部通过 SQL 从现有表计算。

### 2. 电功图与示功图关联数据

48 口井按井号稳定分配正常供液、供液不足、间歇供液、杆柱异常、泵阀漏失和碰泵冲击等典型轮廓，并叠加由井号与采集时刻决定的小幅连续扰动。不同井的冲程、冲次、最大/最小载荷、功图面积和光杆功率保持差异。

反算使用与 `convert_electric_card` 一致的方向：

`P_e = ((F_target - F_static) × r × sin(theta) + T_balance) × omega_motor / (1000 × gear_ratio × eta_trans × eta_motor)`

生成的电流、电压、功率因数与有功功率满足 `P≈√3UIcosφ/1000` 的数量级关系。数据经现有转换、特征提取和诊断服务落库，不在前端伪造结果。

### 3. 功图管控页面

功图档案页增加工况、井号、采集时点、冲程、冲次、载荷范围、功图面积、分析状态及操作；提供工况分布、今日采集/分析数量和异常数量概览。分析页并列展示带坐标的原始电功率曲线与地面示功图，并保留滤波、转矩换算、特征、模板相似度、规则命中、候选工况、产液量和人工复核入口。

在现有菜单体系中强化“功图档案—功图跟踪—智能诊断—产液计量—报警/复核”的下钻关系，优先复用已有页面和 API，不在时限内复制无业务行为的空菜单。

### 4. 一致性与失败处理

- 无功图点集时显示明确空状态，不绘制假线。
- 非有限数值不进入 SVG 属性；坐标域为零时使用安全跨度。
- 旧数据库通过幂等补强逻辑获得新格式功图，重启不重复写入业务记录。
- 原始机器诊断不被人工复核覆盖；待复核状态与复核记录保持一致。

## 验证标准

- 单元测试验证六类目标功图的闭合性、载荷范围、形状差异和电功率反算一致性。
- API 测试验证首页新增字段全部来自数据库且数量可追溯。
- 页面契约测试验证坐标标题、丰富化板块、权限按钮和无前端随机数。
- 运行核心回归、JavaScript 语法检查、Python 编译检查和一键验收冒烟。
- 重启本地服务后用真实浏览器检查首页、功图档案和功图分析三条关键路径。
