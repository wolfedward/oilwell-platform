# 油井平台测试数据与硬件设计交付方案

日期：2026-10-19。状态：用户已确认，先制定 A 包实施计划。当前软件基线：`0c2e6c7d70b0a034f5e070b6d27d754e69d7b8aa`。

本方案响应任务书年度工作任务，不包含专利、奖项、软著及申报数量。目标是在没有现场硬件和实测资料的条件下，交付可复现的测试数据、通过现有系统实际运行产生的验证记录，以及可供厂家工程审查的硬件设计。用户已同意以机理仿真和软件联调表述测试来源。

本稿确定交付范围和验证条件，不代表数据包、硬件图纸或新增软件已经完成。设计通过后，先制定第一批测试数据与隔离联调的实施计划；硬件工程包及统一工作台接入分别制定详细设计和实施计划。

## 1 交付边界

1. 原 8765 演示版独立保留；不改动其源文件、账号或业务库。
2. 现有 8770 工程审查版、8772 完整页面预览和 8774 监控工作台不灌入本批测试数据，不用其服务做故障注入。
3. 生成数据保持仿真来源。虚拟井号不称为脱敏现场井号，模拟校准参数不称为检定证书，软件记录不称为硬件试验报告。
4. 验证报告只记实际执行的步骤、测量值、错误和日志；计划、预期结果、实际结果分列保存。未执行项保留为未执行，不预填通过。
5. 硬件第一版限定低压台架监测设计。没有实物时不声明制板完成、现场保护有效、整机精度、防爆等级或安全认证。
6. 不发布远程启停、Modbus 写寄存器、保护定值远程下发或执行线圈接口。保护回放继续保持物理输出禁用。

## 3 第一批测试包范围

### 3.1 数据来源与用途

包内分为四种场景，每条场景记录生成方法、适用范围和允许验证的结论。

| 场景类别 | 用途 | 不能据此得出的结论 |
| --- | --- | --- |
| 机理模型 | 同周期位移、载荷、角度、功率的单位、能量关系及算法数值验证 | 现场反演精度、全部井况适用性 |
| 信号故障注入 | 噪声、偏置、时移、丢样、削顶、谐波或边带下的算法与质量判断 | 已实际发生某种机械或电机故障 |
| 图形展示样本 | 用户提供的典型功图轮廓、悬停坐标、图例和双图交互 | 经机理验证的故障标签或诊断识别率 |
| 协议与系统异常 | 重复、乱序、断连、错误摘要、权限拒绝和恢复流程 | 物理掉电耐久或现场网络指标 |

生成器应保留场景类别，不能把图形展示样本混入机理模型评估后报告统一准确率。BP 工况模型使用的标签为生成器定义的场景标签，其评价只描述这组仿真数据。

### 3.2 默认规模

以下是扩展生成配置的目标，不是已有数据统计。首先交付可快速复核的小型基准：8 个四通道周期，分为基准、平衡变化、摩擦变化、速度变化及量化噪声、缺样、削顶、已知时差；另有 4 个电流信号案例和协议负例。小型基准通过后才扩展数量，不能用大量相似数据替代关键场景覆盖。

小型周期默认 8 秒、128 Hz、含端点 1025 帧，四通道 i32le 加质量码共 20,500 字节解码数据；每片最多 256 帧。换向索引由实际模型的运动事件确定，不固定为样本总数的一半。功率声明为窗口均值时，须实际积分该窗口。小型电流案例为 16,384 点、1,024 Hz，16 秒，不进行未声明的补零或截短。

扩展配置在生成前做总量预算：

- 8 口虚拟井，14 个完整仿真日，15 分钟统计间隔，每帧 12 个明确单位的标量测点；无缺测基线为 10,752 帧、129,024 个标量值。异常案例单独列出，不静默补齐。
- 112 条日汇总，以相应时间区间的流量、功率和覆盖率计算，不直接复制固定产液量或耗电量。
- 60 个功图周期样本，覆盖正常闭合环、充满度变化、机械负载变化、传感器误差及质量拒绝场景；其中哪些属于机理、信号注入或纯轮廓必须逐条登记。不能为满足数量强行给未建立模型的故障贴机理标签。
- 8 个定子电流信号场景，默认每条 32,768 点、2,048 Hz，即 16 秒；原始信号与频谱输入不经过显示抽稀。另包含采样不足和信息缺失的拒绝案例。
- 恢复拟合、有限候选开停制度、效果比较及保护回放均包含正常、边界、证据不足或不适用案例。测试定值只适用于软件场景，不推荐为现场定值。
- BP 数据先生成 90 条参数场景特征记录，训练、验证、测试各 30 条；按虚拟井、周期和时间隔离，遵守现有每个分区至少六条且包含全部类别等约束。优先使用“合成高摩擦”等参数标签，生成参数不能根据测试集结果反复调整后仍称独立验证。

历史数据使用固定起点、时区、随机种子和生成器版本。快速重放时另外记录仿真时间、运行墙钟时间、重放倍率和时间映射，不把加速后的 14 天称为连续运行 14 天。改变种子、模型或时间起点必须产生新的数据包标识。

完整历史包首先用于离线校验和研究导入；真实网络联调使用预先登记、数量受限的场景子集。报告分别列明离线文件数量和实际入库数量，不把生成的全部历史记录计为已完成网络收发，也不以短时重放代替长期稳定性试验。

### 3.3 产液与用电一致性

同一场景的产液和耗电由运行时长、泵工作参数、充满度、功率及启停制度共同产生，不分别画两条任意随机曲线。

在选定的同工况示例中，负载或有效运行时长增加可以形成产液和耗电总体正相关；不把正相关作为所有工况必须满足的验收条件。低效、空抽、停井等情况允许打破这一关系。

耗电量分开保留输入、回馈和净值；功率为负时不一律截成零。产液量保留其模型假设。日汇总有完整覆盖率和缺测说明，不将瞬时日产率直接冒充完整实测日量。

## 4 同周期功图与模型验证

### 4.1 生成与计算分离

生成器先定义可解释的机械运动、合成载荷和损耗参数，再用正向能量模型得到电功率。合成载荷参考通道与待反演功率通道分别输出；反演程序不得读取参考通道来产生预测值。

第一版限定已声明的刚性运动与能量模型，不默认已模拟完整杆柱弹性波、井下泵阀动力学或变频器。仅能通过轮廓构造表现的工况归入图形展示样本。

生成期望值的正向计算不能调用被测 `predict`、`solve_load` 或生产 `build_geometry` 来反求同一答案。允许复用协议序列化、单位定义和公开校验器；机械公式至少有独立小规模手算或独立实现的基准。共享物理假设仍属于模型内自洽检查，不构成独立实测准确性验证。

保留一组无噪声数值基准，再分别引入量化、测量噪声、载荷偏置、时基误差和模型失配。分别报告误差、有效覆盖及拒算区间，不为了曲线好看修改反演输出。

### 4.2 功图显示

两条曲线使用“电功率反演结果”和“仿真载荷位移参考”名称；没有现场传感器时不显示为现场实测。保留独立勾选、统一单位、合适的坐标比例、细线和悬停点；坐标提示保留两位小数，原始文件不因此降低精度。

图周围显示井号、仿真周期、冲程、冲次、载荷范围、功、来源类别和质量状态。图例或说明保留来源。缺测和拒算区间断线；插值若存在应独立说明，不能让插值点看起来像有效原始采样。

## 5 文件与接口兼容

数据包外置清单版本为 `owp.testpack/1`，与上行报文的 schema 分开。生成配置明确固定种子、逐场景派生种子、Python 运行版本和随机数算法。确定性文件采用固定键排序、UTF-8 和 LF；数值量化规则写入配置。数据包包含以下内容；完整字段字典和工具入口在 A 包实施计划中固定。

| 内容 | 形式 | 作用 |
| --- | --- | --- |
| 包清单与来源 | JSON | 包标识、生成器代码版本、种子、仿真时间范围、参数摘要、文件摘要和场景用途 |
| 生成配置与预期结果 | JSON | 可复现输入、物理假设、故障注入、预期接受或拒绝原因及预先固定的数值容差 |
| 标量遥测 | OWP-EDGE/1.0 原始 JSON 字节及便于检查的 CSV | 原始报文用于链路；CSV 不是原报文摘要替代品 |
| 周期与电流录波 | OWP-WAVE/1.0 的 `.owpwave` 文件及索引 | 复用现有离线导入与波形校验器 |
| 工程研究输入 | 现有 study envelope JSON | 调用恢复、调度、工况、频谱及保护引擎 |
| 实际运行证据 | 独立运行清单、JSON 报告、日志、曲线及摘要 | 实际代码版本、环境、输入、输出、耗时、错误及完整性核对 |

不向严格的 v1 遥测或波形报文随意添加 `seed`、`scenario` 等未知字段。额外来源、假设和参数写入外置包清单，并用现有引用字段关联。

- 标量采用 `source=software-fixture-modbus-tcp`；Modbus 适配目前默认写 `modbus-tcp`，本包须通过仅限隔离联调的适配层在实际读取后生成上行样本时保留虚拟来源，不在入库后改写原记录，不改变实际设备默认行为。包内预生成报文与实际网关创建的随机 message_id、boot_id 分开登记，不能假定每次实跑原报文完全相同。
- 波形使用 `source_kind=synthetic`；合成通道使用 `measurement_source=synthetic`。配对用途保持 `software_pair_test`，不得借测试资料进入 `field_pair_input`。
- 研究 envelope 使用 `source.kind=software_fixture`，在 `description` 和 `references` 中关联包标识及摘要；不使用 `submitted_observation` 冒充采集资料。
- 来源、配置和软件用途校准证据 ID 从实际证据服务创建并复核后取得；数据包不预造“已审核”的证书或服务 UUID。缺少关联证据时允许保留原始归档，但不绕过配对和反演的准入检查。
- 数据包确定性不包括实际运行产生的接收时间、账号审计时间或运行随机身份。生成文件的摘要与运行回执的摘要分开核对，不修改服务时间来追求日志字节一致。
- 单个波形遵守当前 manifest、chunk、解码总量和文件总量限制；超过预算应先拒绝生成，不截短后冒充完整数据。包总量上限默认 256 MiB，不含实际运行日志与系统备份。

## 6 隔离联调与报告

### 6.1 真实软件路径

标量链路采用本机 Modbus TCP 软件设备端、现有只读网关、MQTT Broker、中心入库、台账与查询 API。软件设备仅接受 FC03/FC04，拒绝写功能码；台账按实际 Modbus 传输类型及寄存器点表登记，不照抄现有 `mqtt_direct` 测试记录。第一版不声称完成 RTU 物理串口联调。

同步周期和高频电流通过现有波形合同导入及装配，不能用 15 分钟或秒级 Modbus 标量轮询代替同步 ADC。首版先完成离线原文导入；在线分片及回执作为单独验证场景，只有实际执行后才在报告中记为验证通过。

研究计算使用实际引擎和 HTTP 服务。输入和预期结果在运行前固定，算法结果由运行生成，不能预写成功 JSON。数据包内的预期动作不是实际硬件反馈。

现有 `review` 与 `monitoring` 是不同运行配置。本包复用各自独立的新建测试实例，不暗中合并运行配置，也不宣称因此完成全部生产页面的统一集成。共同数据包标识用于结果对照，实例、数据库、账号和实际运行记录分别标识。

现有审查部署的 Broker 设置为 `persistence false`。第一批的重启检查限定 HTTP、中心消费者及本地队列恢复，不将其写成 Broker 持久会话或断电恢复通过。如要验证 Broker 持久性，需另建并封存有明确存储和权限的测试配置，补齐独立测试；不手改现有密封安装或拿客户端重发代替 Broker 持久化证据。

### 6.2 实例所有权与权限

测试工具只能使用本轮新建、带所有权标识的目录、数据库集群、缓存和 Broker。绑定 127.0.0.1，端口在启动前验证空闲，避开既有安装的保留端口。认证资料保存在本机私有目录，不进入公开数据包或 Git。

测试发布身份只允许本包明确列出的软件设备主题，不给生产主题通配权限；网关、中心、回执发布器和查询账号分权。原有密封安装配置不改写。新增初始化工具须验证固定代码、环境标识和实例身份，不能接收任意业务 DSN 后执行清理或迁移。

仅停止本轮创建且进程身份相符的进程；端口冲突或目录已存在时停止该动作，不结束未知进程、不覆盖原目录。失败数据和日志保留，重复运行产生新 run ID，幂等重发则保留同一消息的原始字节。

设备台账与点表通过实际接口建立，测试人员身份由独立测试账号模拟；自动化双角色流程在报告中标明“软件权限流程测试”，不伪装成真实人员签字批准。

### 6.3 错误场景

至少覆盖原样重发与去重、同 ID 不同字节、坏质量、时移与缺片、摘要错误、未知身份、权限不足、上游撤销后下游受限、软件网络断连及所属服务重启。超过容量的输入应明确拒绝，不静默丢弃后返回成功。

所有故障注入限定本轮实例。磁盘满和物理断电不在本轮真实故障范围内；若通过替身或软件错误注入测试，只记录其实际测试层级，不称作物理磁盘或断电试验。

## 7 硬件工程包范围

硬件工作包 B 从现有 `assets/open-interface/HARDWARE.md`、接口文档和保护参考出发，保持低压台架用途；必须另行完成元件级详细设计审阅后才开始出图。

### 7.1 设计架构

建议按同步采样与实时处理、通信与存储、电源与接口三个部分划分原理图。首版允许采用已明确电气边界的外部低压传感器调理模块；不设计现场市电直接输入或动力开关回路。

电参同步 ADC、承担 DSP 职责的实时控制器、通信 MCU 和隔离 RS-485 沿用现有候选路线，但须按具体料号、封装和数据手册重新核对。C2000 实时 MCU 承担 DSP 分工不等于两颗安全冗余处理器；STM32H563 与 H573 的安全外设不能混为同一器件能力。

源数据使用与测试包相同的单位、极性、通道角色、周期索引、校准版本和时基定义；测试包的采样参数只是软件配置，不作为硬件已实现采样指标。独立 ADC 的群延迟与通道时间对齐必须保留校准和实测验证入口。

硬件详细设计必须核对波形容量：若 8 路均为 8 kS/s，每点 4 字节数值加 1 字节质量，60 秒为 19,200,000 字节，超过当前 16 MiB 解码限制。可以评估缩短录波窗口或将辅助通道经有记录的滤波后降采样；不能只改采样率标签。同步控制还须区分 ADC 采样时钟、DRDY、SYNC/RESET 和滤波稳定期，不以一次 GPIO 脉冲声称已完成通道同步验证。
