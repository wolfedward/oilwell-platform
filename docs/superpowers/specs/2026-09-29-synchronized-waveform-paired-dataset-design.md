## 4. 统一数据契约：OWP-WAVE/1.0

### 4.1 报文与身份

在线主题：`oilfield/v2/{gateway_id}/{device_id}/waveform`。`oilfield` 可按现有安全前缀规则配置。仅 QoS 1、非 retained；独立消费者与订阅，不让 v1 消费者误收。入口 schema 固定为 `OWP-WAVE/1.0`，`kind` 为 `manifest` 或 `chunk`。

共同字段：schema、kind、gateway_id、device_id、capture_id。capture_id、boot_id 和 cycle_id 为 UUID，中心逻辑唯一键为 `(gateway_id, device_id, capture_id)`；主题与字段必须一致。设备重启必须产生新的 boot_id，不能依靠重启后复用的周期数字判定同一次测量。

严格 UTF-8 JSON；拒绝重复键、未知字段、非有限数值、错误类型、尾随内容和越界整数。布尔值不算整数。绝对起始样本序号以及所有纳秒时间/偏移/不确定度统一使用十进制整数字符串，范围不超过带符号 64 位整数；前后端不得用 Number 丢失精度，序号和不确定度不得为负。窗口内 sample_start/sample_count、chunk_index/chunk_count、字节数、帧数和采样率分子/分母为 JSON 整数，均不超过 2147483647，并执行各自更小的业务上限；采样率分母不超过 1000000，分子分母须约分。JSON 嵌套深度最多 16。

manifest 保存**发送方定稿后的精确字节**，SHA-256 为这些字节的摘要，不做 JSON 重排后再算摘要。相同采集编号只能对应一份 manifest。chunk 必须引用该 `manifest_sha256`。运输时间、操作者、HTTP 请求或 MQTT 属性由中心另外记录，不能加入 manifest 导致同一录波在线/离线内容变更。

### 4.2 manifest 的必需信息

“必需”包括必须显式为 null 的未知信息；未知可存，但不能偷偷补成 0 或系统时间。

| 信息组 | 内容及含义 |
| --- | --- |
| 采集标识 | capture_id、采集端 boot_id、capture_kind（cycle/event）、source_kind（synthetic/bench_measurement/field_measurement/unknown）、厂家及采集软件版本 |
| 来源证据 | 可为空的来源说明/附件摘要引用；source_kind 是设备声明，中心另存核查结果，不把它当已认证事实 |
| 时间锚点 | UTC 起点 `YYYY-MM-DDTHH:mm:ss.ffffffZ` 或 null、UTC 不确定度 ns 或 null、clock_domain_id、同步证据记录 ID 或 null |
| 周期 | cycle 时必须有 cycle_id、周期起止相对 ns、方向、零相位定义、参考通道及参考事件；event 可无完整周期，不因此伪装成成对功图 |
| 采样组 streams | 每组 stream_id、实际来源 gateway/device/boot、采样率分子/分母、起始样本序号、相对采集起点的 ns 偏移、总帧数、帧宽、分片帧数/片数、整组解码字节数及 SHA-256 |
| 通道 channels | 每通道稳定编号、物理量、单位、编码、测量来源、采样配置版本与校准记录 ID（可为 null）；区分瞬时值、RMS、窗口平均值和算法推算值 |
| 采集窗口 | 最大相对时间跨度；如超出本协议上限，厂家生成另一个 capture，不截断后仍沿用原编号 |

UTC 格式首版不接受闰秒词法 `:60`；采集端如发生无法表达的 UTC 跳变，应分段并标明时钟未知，不把样本压缩/重复到相邻秒。接收时间不能替代采样时间。纳秒字段表达计算和对齐单位，不承诺设备有纳秒级精度。

多组可有不同采样率。单组内各通道必须同一时钟、同一采样时刻定义；不同 ADC 群延迟仍须分别描述。跨设备数据可装入同一 capture，但必须有共同时间域及可核对的映射证据。只填相同 clock_domain_id 或 cycle_id 并不能建立同步可信性。

### 4.3 样本编码、分片和缺失

初版只支持 `i32le` 与 `f32le`，不支持压缩、任意编码、外部 URL 或动态解码插件。24 位 ADC 的有符号原码在适配端符号扩展到 i32le，并在采样配置记录有效位数。不同通道可用不同的上述编码。

数据按“帧优先、manifest 中通道顺序”排列。**每个通道值为 4 字节数值 + 1 字节质量标记**，因此组帧宽为 `5 × 通道数` 字节。质量字节：0=good、1=missing、2=clipped、3=bad、4=uncertain，其他值拒绝。missing 数值四字节必须全零，但这个零不是测量值，任何计算/绘图必须先检查质量标记。f32le 的所有非缺失值必须有限；无穷与 NaN 不能充当缺样标记。

缺样仍占据原采样序号，不挪动后续样本时间。未知质量不能默认 good。原始数值不做两位小数截断；小数位仅是界面显示规则。

chunk 字段包括 stream_id、chunk_index、sample_start、sample_count、manifest_sha256、data_sha256、data_base64。sample_start 是该组窗口内从 0 开始的帧索引；绝对序号等于 manifest 的起始序号加此索引。manifest 声明每片帧数，末片允许较短；片数、索引、字节数必须能相互计算核对，禁止重叠、越界或靠“收到多少就算多少”。

data_base64 为无空白、带标准填充的标准 Base64；data_sha256 对解码后的完整分片字节计算。整组摘要对按索引拼接的解码字节计算，包含质量标记。manifest 摘要已绑定所有组的摘要和元数据，不再发明另一个含糊的“整段摘要”。哈希证明内容一致性，不证明设备身份、实测真实性或数字签名。

### 4.4 初版硬上限

以下是本协议首版实现边界，不是现场容量承诺；服务器还可配置更低额度，不可静默接受更大输入。

| 对象 | 上限 |
| --- | --- |
| manifest 精确字节 | 64 KiB |
| 单个 chunk 报文精确字节 | 256 KiB；解码数据最多 128 KiB，必须整帧 |
| 单 capture | 16 MiB 解码数据、32 MiB 原始报文字节，最多 512 片 |
| 采样组织 | 最多 8 组、合计 32 通道；每组至少 1 帧 |
| 时间与频率 | 窗口跨度最多 60 s；采样率为正有理数、1—128000 S/s，仍受总字节数约束 |
| 单原始曲线窗口读取 | 每通道最多 20000 帧；显示摘要接口每通道最多 2000 点 |

电参 8 kS/s、载荷/位移 100 S/s 是当前参考硬件的候选设计点，不是强制所有厂家固定采用的采样率，也不自动决定算法带宽或精度。[参考硬件设计](../../../assets/open-interface/HARDWARE.md)。

## 5. 离线文件与在线接收使用相同内核

离线文件扩展名 `.owpwave`，为 UTF-8 单行 JSON 报文序列：首行 manifest，其后为 chunk，行分隔仅 LF，允许最后一行无 LF；禁止 BOM、空行、多行对象和 CRLF。去除行分隔符后每行就是 MQTT payload 的精确字节，不重新序列化。文件仅含一个 capture，最大 `32 MiB + 513 字节`（报文额度外只容许行分隔）。不接受 ZIP 或可执行脚本，避免压缩膨胀、路径穿越及解包歧义。

文件校验器先验证全部行、清单引用、总量及摘要，输出机器可读结果；不得把错误文件“修补”成成功。浏览器导入前执行等价预检，但服务端仍独立验证每条报文。上传通过有权限的导入会话逐片发送；HTTP 请求不把整个 32 MiB 文件一次读进通用 JSON 处理器。

导入会话记录操作者、文件 SHA-256、字节数、预期行数、末行是否带 LF，以及收到的行号/原始字节关联。每文件必须恰有一份 manifest 和全部预期 chunk 各一份；chunk 行可乱序。支持按缺失行继续上传；会话封存由服务器按行顺序及末行 LF 约定核对文件摘要。取消或失败不删除已持久原文；内容已收齐但文件来源封存未完成时，来源资格仍受限。会话上限和 capture 上限同时生效，换 session_id 不能规避配额。

在线与离线都调用同一合同验证器、分片保存器和组装器，不能复制两套宽严不同的规则。离线导入有 HTTP 保存结果，不产生 MQTT 应用回执。在线原文再被离线导入时复用内容事实，追加运输/导入关联，不重复复制录波或覆盖早先来源。

## 6. 持久化、确认与恢复

### 6.1 中心记录与事务

`waveforms` 中分开保存以下实体：不可变原文 facts、观察/导入关联 observations、manifest/分片内容索引、可恢复 assembly_jobs、不可变 completion 结果、应用 receipts 与可变 delivery 租约、quality_runs、calibration/config/evidence 版本、pair_reviews、datasets/versions/members、audit/operation_receipts、容量台账。

初版只在原文事实中存精确 BYTEA；解码内容按分片读取，不额外长期保存第二份相同二进制。不得使用 JSONB 替代精确原文。元数据索引用于查询，和原文关联受约束。后台任务可重建派生索引，不可改写原始测量。

收到一条报文时，**配额预占/扣账、原文及索引、观察状态、适用的待发回执同一事务提交**。事务提交失败或结果不确定时不返回持久成功；在线不发送手动 PUBACK，离线返回可重试的不可用结果。数据库故障、磁盘满、程序不变量错误不能冒充“输入已隔离”。

台账、校准查询失败不影响字节接收，但会让质量评估停留在待评估，禁止静默通过。注册未知、过期校准和 bad 样本属于质量问题，不是 JSON 隔离理由。

### 6.2 幂等、乱序与冲突

- 相同 capture 的相同 manifest 原文字节、相同 stream/chunk_index 的相同报文字节重投，只更新有界观察计数并调度已有回执，不复制样本。
- 同逻辑键不同原文字节（包括“仅换一种 JSON 排列”）为冲突。保留冲突证据、不覆盖首个事实；需要更正时使用新 capture_id，并显式关联被更正的旧记录。
- manifest 未到时的分片可在独立孤片额度内保存，标记待清单；不视为合格录波。之后清单到达再核验引用及布局。无效孤片不得抢占另一份 manifest 的有效分片槽位。
- 乱序、重复、消费者/组装器并发由唯一约束及有限锁保护；收到全部预期片之后，组装器逐片核验完整摘要和质量编码。
- 组装结果一旦封存不可重写。后到的冲突不会抹去此前已封存事实，但形成追加冲突事件，阻止新数据集准入；已冻结版本显示后续告警和使用限制。

### 6.3 状态与回执

capture 接收状态为 collecting、complete、invalid；stalled 是 collecting 超过 24 小时无新增有效片的派生告警，迟到的原片仍可恢复，不自动删除。complete 只表示清单声明的字节收齐且结构/摘要相符；含 missing 的完整录波仍可 complete，但不能因此成为合格校准样本。invalid 为整段冲突/布局/哈希核验失败的封存结果。

独立回执 schema `OWP-WAVE-ACK/1.0`，主题 `oilfield/v2/{gateway_id}/{device_id}/waveform-ack`。不修改 `OWP-INGEST-ACK/1.0`，旧网关不得把新回执当标量确认。回执最多 4 KiB，包含 receipt_id、gateway/device/capture、scope、manifest_sha256（可安全取得时）、原始报文 SHA-256（message scope）、stream/chunk_index（适用时）、status、受控 reason_code、UTC recorded_at。

| scope / status | 何时产生 | 发送端能做什么 |
| --- | --- | --- |
| message / stored | 单条 manifest 或 chunk 已持久保存 | 停止该条的常规重发；仍保留整段可恢复副本 |
| message / quarantined | 永久输入错误的原文和拒绝事实已持久保存，且能安全关联目标 | 停止盲目重发，保留本地副本等待处理 |
| capture / complete | 组装校验成功、封存事实及待发回执同事务提交 | 可将整段标为中心收齐；不等于质量合格，也不自动删除文件 |
| capture / invalid | 不可恢复的整段核验失败结果已封存 | 标为需处置，不篡改原录波或沿用编号覆盖 |

捕获级回执必须绑定 manifest 摘要。无法安全获取身份/关联摘要的坏报文只保存，不向猜测的设备发送回执。永久错误分类包括主题/传输约束、UTF-8/JSON/字段、引用、布局、摘要、幂等冲突；实现时固定有限原因枚举与优先级，不能捕获所有异常后发送 quarantined。

QoS 0/retained 报文按不合规运输留证，不计入可靠通道；隔离单报文硬上限为 256 KiB，超过该上限不假称已保存，入口/Broker 必须有相应包大小限制。订阅保留 retain 原标志。MQTT 回执发送采用持久 outbox、租约重试和代际校验，不允许旧租约提交覆盖新状态。恢复重发相同 manifest 可重新调度已有整段回执，发送端无需依赖一次性的完成通知。

MQTT 本身的确认不等于数据库或整段业务完成，本设计的后两种确认属于独立应用协议。[MQTT 5.0 §4.3](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html)。

### 6.4 厂家/网关持久发送工具

增加独立的波形文件发送器，不改普通 Modbus 轮询器。先验证并把文件精确内容写入专用持久队列，再发送 manifest/分片；记录每条应用确认和整段结果。收到回执前校验 schema、主题、身份、capture、manifest 和相应报文摘要。伪造/未知/超期会话回执不能清除队列。

进程重启、断网或 Broker 重启后按保存状态继续。已收齐录波可转归档状态，首版不自动清除归档或失败副本；空间不足停止接纳新的发送文件并告警，不覆盖待确认内容。旧标量队列无需迁移。接收/发送工具本身不产生任何物理采样真实性声明。

## 7. 同步、校准与来源证据

### 7.1 时间模型

每组第 i 帧的名义采样时间为：采集 UTC 锚点 + 组起始偏移 + `i × 采样率分母 / 采样率分子` 秒，偏移 ns 先换算为相同单位。UTC 未知时只计算相对时间。使用整数/有理数运算确定索引，不逐帧累加舍入后的浮点周期。原始序号随 boot_id 解释；计数复位或溢出必须开启新 boot/capture，中途采样率改变开启新 capture，不能重排样本使曲线连续。

每个通道有记录在案的时序修正量 `time_correction_ns`：**物理采样时刻 = 名义采样时间 + 修正量**。例如确认存在正群延迟的输出通常需要负修正，但平台不代厂家猜符号。修正量、残余不确定度及其校准依据一起版本化，原始时间不覆盖。时钟频率误差、触发偏差、采样间通道偏斜、滤波群延迟分别记录，不把一个 NTP 状态当成全部同步证据。

共同时间基准、起始触发与跨通道时延是不同问题；同一触发并不能证明后续采样一直同步。[NI 时序与同步说明](https://www.ni.com/en/support/documentation/supplemental/06/timing-and-synchronization-features-of-ni-daqmx.html)。本系统要求的是可检查的证据模型，不绑定 NI 硬件。

首版同步证据支持两类：同一采样时钟的分频采样；有校验报告的线性时钟映射。后者必须给出适用时间窗口、偏移/频率误差界及参考事件，窗口外不外推。只有软件收到时间、只有相同时间标签或仅相关性对齐的情况均标记 unknown，不取得定量配对资格。

对目标周期计算保守的跨通道相对时间误差上界：所用映射残余误差、通道修正残余误差以及按周期时长累积的频率误差界相加。共享时钟的公共偏差不重复当作相对误差；但不能未经证据就假定误差相互抵消。UTC 绝对不确定度另用于历史井绑定的边界判断。任一必要误差项未知时，总上界为 unknown，不是 0。

### 7.2 不可变配置/校准记录

波形的采样配置独立于标量 Modbus 点表，不能仅凭 point_map_version 已批准就认为 ADC 校准完成。保存以下内容和来源附件的摘要/受控存储引用：

- 实际设备、传感器编号、通道连接、物理量/单位、ADC 有效位数、输入量程、增益/偏置、原码到工程量公式；首版公式仅 `value × scale + offset`，不执行上传表达式。
- 三相电压的相对参考（相对中性点/线间）、相序、电流方向；瞬时电流与 RMS 电流不同物理量，不可混用。
- 模拟抗混叠及数字滤波配置、通道时延/修正、采样率、时钟/触发方式；未知字段明确为 null。
- 载荷 kN、位移 m、角度 deg 的标定范围、方向、零点；计量依据、方法、校准时刻、有效期、误差/不确定度说明。
- 对应标量点表的 reported version（存在时）只作旁证，仍与中心 expected version 分别显示。

内容定稿即不可改；状态通过追加 review/revoke 事件表示。新版本不覆写旧记录，记录作废不删除历史依据。创建人与批准人必须不同账号；管理员有全部页面/能力权限，但不能单人绕过双人复核。证据附件只允许受限大小的资料上传/下载，不自动取回任意 URL 或执行内容；首版仅接收 PDF、PNG、JPEG，每件最多 4 MiB，每记录最多 8 件，受总配额和权限控制，不内嵌不可信活动内容。

批准记录只表示资料已按平台流程复核，不是软件替厂家签发校准证书。synthetic 校准记录只供软件向量验证；其数据不得进入现场实测集合。没有校准设备并不妨碍录波入库，但阻止声称精度达标。

### 7.3 来源与历史井归属

中心记录声明来源、接入通路、操作者/受控 Broker 接入配置引用、核查人和核查证据。消费者看到的 topic/client 数据不冒充 Broker 已认证的发布者身份；生产接入必须另有按身份限制的 Broker ACL 和部署核验。离线文件中自称某设备不能自动获得这个身份的可信来源资格。

每个实际采样源按其采样窗口和 UTC 不确定度，关联历史登记状态、井绑定及采样配置有效区间。采用半开区间 `[起点, 终点)`；整个扩大后的不确定时间窗口必须属于同一有效井绑定，跨井/跨状态/跨校准有效期边界一律不自动配对。不同来源设备必须解析到同一生产井。缺少 UTC 时保留相对时间图，但井归属为未证实。

评估保存台账修订、具体绑定/状态记录 ID 及当时的内容快照；后续更正只能生成新评估，不随当前井号变动而改历史。来源声明从 synthetic 改成 field_measurement 必须是新的、真正有依据的采集记录，不能给旧测试向量改标签。在线重发和离线补传都不改变这个规则。

## 8. 质量门禁和成对输入

### 8.1 用途分层，而非一个总“合格”标志

质量评估是不可变的 quality_run，绑定原文摘要、验证器版本、资料版本、台账快照和 profile 版本。结果只用 eligible、ineligible、pending 三类，附逐项 reason_code 和证据。人工备注与机器判定分开；人工不能关闭 missing 等硬失败使其变为 eligible。

| 用途 | 首版准入规则 |
| --- | --- |
| raw_archive 原文研究留存 | 格式可识别且整段 complete；不保证同步/计量正确，允许质量差及未知来源，但必须显示问题 |
| software_pair_test 软件联调配对 | 完整、无缺样、校准和时钟测试向量自洽、周期可定位；仅 synthetic/台架软件验证资料，不列为现场实测 |
| field_pair_input 现场成对输入 | 在完整性之外，要求经核查的实测来源、整周期同井/同时间域、有效采样配置及校准、全部所需通道 good、足够的通道/周期覆盖和已批准的现场试验 profile |

预置软件 profile 只用于流程测试。现场 profile 默认没有生效版本，不能因“还没有设备”自动采用测试阈值。批准现场 profile 必须填明目标设备类型、用途、必需物理量、各通道最低采样率、最大相对同步误差、适用量程、必要证据和试验依据；这些值存入固定字段而不是任意脚本/规则语言。创建/复核使用同样的双人机制。

参考硬件中的 1 ms 是待验证设计目标；本设计不宣称它适用于所有反演模型，也不把文献中别人的误差指标变成本项目承诺。即使 field_pair_input 通过，也仅代表**符合指定采集试验条件的候选样本**；模型用途、误差及现场适用性仍须 WP-05 验证。

至少输出以下质量原因：incomplete、capture_conflict、unknown_origin、unregistered、unbound、binding_boundary、inactive_source、unknown_clock、sync_budget_exceeded、missing_samples、bad_or_clipped_samples、unknown_units、unknown_calibration、calibration_expired_or_revoked、config_mismatch、cycle_unresolved、insufficient_coverage、unsupported_quantity、evidence_unavailable。系统依赖故障归 pending，不把故障渲染成数据合格或记录数 0。

### 8.2 配对的严格含义

本轮“成对”首先指**同周期电参输入 + 独立载荷/位移实测输入**，不是先生成两条相似曲线再称其相互验证。算法反演结果是一种另行版本化的派生产物，不是传感器真值；生产反演运行与模型准入放在 WP-05。

配对候选由共同录波中的参考周期，或经明确同步证据连接的两个 capture 产生。禁止仅按最近时间、相似轮廓或相同井名自动批准。候选必须明确选中的电参组、载荷组、位移组、周期参考和时间窗，附全部 capture/stream/calibration/config/quality_run ID。

首版配对所需电参为以下任一类，并在数据集分开标明：

- 同步三相瞬时电压/电流，量纲及接线参考明确，供后续模型使用。
- 设备给出的三相总有功功率周期序列，须记录计算方法、平均窗口、时间标记约定及带宽依据；不把 5 秒级标量快照插值成周期电功图。此类不能替代原始电流频谱样本。

载荷与位移必须来自传感器测量通道，不能采用待验证反演模型的输出；必须有足够覆盖并保持上下行顺序。若原始功率含回馈负值须保留，不为了符合图片裁掉负值。`u × i` 的瞬时和不能在没有平均窗口定义时标为总有功功率。

一个周期以实际参考事件界定，记录起点、换向点、终点及方向，时间满足起点 < 换向点 < 终点。整个周期必须位于所有必需通道的有效时间支持区间内，参考边界须有有效观测或有效相邻点支持，不靠外推补齐；周期外采样可作边界支持但不混入周期成员。由周期时长算冲次；由校准位移极差算该周期冲程，连同有效样本数和来源显示。按时间均分得到的横轴只能叫“归一化周期时间”，不能冒充实测曲柄角；曲柄角必须有测量或明确版本化机构换算依据。

允许只读对齐预览：以传感器有效采样时刻为基准，另一通道只在相邻有效点之间线性插值，不外推、不跨缺失区间，间距不得超过该通道两个名义采样周期。预览保存对齐方法版本和使用的原始索引；不把插值后的点覆写为测量点。定量准入仍执行 profile 的覆盖与误差规则，不能以预览“看起来对齐”替代。

人工复核可接受或拒绝一个已通过硬门禁的候选，填写说明；资料不足的候选只能保留待核查。变更所选周期、资料版本或对齐方法会形成新候选版本，旧审批不沿用。复核人不得是该候选的提交人；算法工程师可以准备样本，业务复核员/获授权生产工程师负责独立核查。

## 9. 数据集冻结与可复现导出

数据集有可修改草稿和不可变版本。具有 waveform.dataset.manage 的用户准备/提交草稿，由不同账号且具有 waveform.review 的用户审核冻结。冻结时在同一事务重新核验成员引用与限制状态，保存用途、来源类别、profile、评估/复核版本、成员清单、划分方案、生成者/审核者及精确清单字节 SHA-256。最多 1000 个配对成员/版本；大集合必须拆为多个版本，不一次性无限加载。

- 冻结只引用封存且满足该用途的成员；原文留存集合可以包含不合格资料，但其用途必须是 raw_archive，不能换标题变成校准/验证集。
- software_pair_test 与 field_pair_input 不可混为一个现场验证集；真实来源未核查不允许降格标成“已实测”。
- 成员标记 train/validation/test/unassigned。标称跨井验证时同一 well_id 只能属于一个分区；按时间留出时训练区间必须早于验证/测试，区间边界与留出间隔写入版本，保守按区间含端点检查，禁止重叠。划分类型为 none 的只能作收集集。
- 同一 capture、同一物理周期及其不同重采样/对齐版本不得跨分区。按来源设备+boot+周期/时间窗建立关联组，不能换 capture_id 绕过重复检查。未能证明相互独立的样本不进入标称独立测试集。
- 后续校准作废、来源质疑或冲突不改历史版本与摘要；追加限制通知，默认禁用其新的训练/验证用途导出，并保留有权限的历史证据导出及原因说明。

导出由有权限的用户发起并记录审计，提供精确版本清单和逐 capture 的 `.owpwave` 文件/摘要；不临时拼一个无大小限制的 ZIP。导出顺序固定为 manifest、按 manifest 组顺序及 chunk_index 递增的各片，每行带 LF；各行原文字节不改。导出文件摘要与导入来源文件摘要分别列出，行序/末尾 LF 不同时不得冒称两个文件逐字节相同。每个文件带内容长度、固定安全文件名及下载审计，下载中断可重试原字节。生产资料不会随公开 Git 仓库、厂家示例包或公共静态资源目录发布。

本轮不训练模型、不自动生成准确率报告；WP-05 消费上述版本，才能在固定输入上比较参数辨识、规则、统计或 BP 等模型。

新增“同步波形与数据集”入口，包含接收清单、波形详情、配对复核、数据集四个工作视图；校准/来源资料在详情关联面板中管理，不重建整套门户。

- 接收清单分别显示通路、收齐状态、质量用途状态、缺片数、源设备/井归属及时间依据，能筛选问题记录并跳转台账。
- 波形详情显示实际通道、单位、采样率、周期/冲程/冲次、时间误差依据、校准版本。质量差的位置有明确断口/区段标记，不连线跨过丢点。
- 载荷—位移图来自传感器原始数据与已声明校准；电参图显示所选真实物理量。没有可用通道时显示原因，不自动画一条参考形状补空。
- 线图默认仅曲线，悬停才显示点，横纵坐标数值保留两位小数；另给原始样本序号与精确时间。精确时间/原码/下载数据不截成两位。
- 大录波显示分桶首末/极值摘要，保留缺口；提示“显示摘要”，缩放后再请求有界原始窗口。悬停只指向实际保留样本，不伪造桶平均为原点；载荷—位移图按时间顺序选点，不按位移排序破坏闭环。
- 配对复核展示时间/井号/来源/校准门禁和同周期输入；生产反演尚未运行时明确显示“待模型工作包接入”，不伪造第二条反演曲线。原演示版已有双图显示保持不变。
- 页面请求取消或切换井/录波后，旧响应不得覆盖当前选择；文件上传中断、重复提交、会话失效有可恢复反馈。
- 未配置为 disabled；配置/数据库错误为 unavailable；权限不足为 forbidden；合法查询无记录才是 empty。三者不能统一显示“暂无数据”。

## 11. 容量、安全与运行边界

新模块独立进程、独立 MQTT client_id/会话/凭据；故障和配额不能消耗或锁住 v1/WP-03 的容量台账。数据库短事务、有限超时、按 capture 锁和有界任务队列；运行时必须配置系统及每网关的报文字节数、事实数量、附件字节数、未完成 capture 数和孤片额度。没有显式额度拒绝启动。

初始联调上限建议：每网关最多 4 个未完成 capture（含孤片），每 capture 孤片最多 512 KiB；全局 64 个未完成 capture，原文 1 GiB、附件 128 MiB、隔离原文 16 MiB，最多 100000 条原文事实。它们只作为隔离测试配置，不自动成为业务环境设置。接受 manifest 时为该 capture 预占 32 MiB 原文额度（包括已有孤片），封存后释放未使用预占；实际扣账不得突破该额度。孤片转账不能双重计费。原文每条至少按 1 KiB 计费，并对导入关联、审计、回执/重试记录设置有界数量或合并计数，不能靠零字节/重复请求耗尽元数据表。

配额不足时不覆盖、不删除未完成/已冻结数据，不发送成功确认；HTTP 返回可识别容量错误，MQTT 发送器退避并保持本地副本。每网关划定原文/隔离等额度，其配置之和不得超过相应全局额度。各网关使用独立持久 MQTT 消费会话和有界工作队列，禁止在共用会话中因一台网关回压而反复断开其他网关；后台工作公平调度。受控订阅按明确配置的网关建立，这不等于该网关下的设备已通过生产台账注册。协议入口和 Broker 另限制连接速率/包大小。这样的隔离防止单网关配额耗尽拖停其他网关或标量遥测；数据库整体宕机、全局物理磁盘满仍会影响依赖它的接收服务，不承诺消除共享基础设施故障。

逻辑配额不等于 PostgreSQL 物理磁盘占用：索引、TOAST、WAL、备份均另占空间。实现必须报告逻辑使用量、积压/最老等待时间、组装失败、回执重试和依赖健康，并提供磁盘监控/停收说明。硬盘耗尽后的恢复不能靠“返回成功但未落盘”。未完成资料自动过期清理、全量归档迁移和连续高频无限留存不在本轮；无批准清理策略时以告警+停收保护原文。

以本契约 4 字节值+1 字节质量计算，6 路 8 kS/s 电参录波 10 s 为 2,400,000 解码字节，再加低速通道、Base64 和元数据；不能继续使用 ADC 原码 3 字节的容量数字估算传输/数据库成本。只上报选定周期或事件窗口，不假设持续全天上传。厂家本地循环采样存储和待传文件队列必须分开，待确认文件不可被循环覆盖。

非本机生产链路要求 TLS 校验证书和主机名、每设备/网关最小主题 ACL；回执发布者不能冒充采集端，采集端不能写别人的上行或回执主题。密钥在私密配置/凭据存储中，不能进源码或下载包。部署范围不包含自动开公网端口或绕过证书校验。

## 12. 验证与验收矩阵

以下是实施后必须产生的证据，**不是目前已通过的结果**。以真实 PostgreSQL/MQTT/HTTP 联调为核心，不能仅用 mock 或截图代替持久化与权限测试。

| 编号 | 实验 | 必须看到的结果 |
| --- | --- | --- |
| W04-01 | 厂家自检、MQTT、离线导入跑同一向量集 | 合同判断与内容摘要一致；运输来源不同且可追踪 |
| W04-02 | 正常数据、坏编码、重复键、bool/超大整数、NaN/Inf、单位及长度边界 | 各入口同样拒绝不合法输入；合法大序号不失真 |
| W04-03 | 丢片、乱序、孤片、重复片、同键异文、末片边界、整组摘要错误 | 不误封存、不覆盖；补足原片才 complete；冲突持久可查 |
| W04-04 | 接收事务提交前/后杀进程、数据库短断、确认丢失、回执延迟与旧租约 | 未提交不确认；已提交可恢复，不重复样本，不被旧状态回写 |
| W04-05 | 发送端、组装器、Broker 重启 | 本地副本和中心任务恢复；仅 Broker PUBACK 不释放整段 |
| W04-06 | 超包/超片/超 capture/孤片/附件/元数据额度、多网关竞争 | 有界拒绝和退避；其他网关与 v1 标量仍能工作 |
| W04-07 | 不同采样率、已知时间偏差/延迟/频率误差、计数复位及缺样 | 原始索引/缺口保留；修正符号、误差上界和覆盖判断正确 |
| W04-08 | 迁井时刻、窗口越界、UTC 未知、校准过期/作废、资料依赖不可用 | 不按当前井号错配；不可用为 pending，硬失败不能人工放行 |
| W04-09 | 假现场来源、合成向量、RMS 冒充瞬时电流、插值假功率、跨周期相似图 | 能留证或按合同隔离，但不取得现场配对/频谱样本资格 |
| W04-10 | 配对自审、无权限调用、跨 Origin、注销/撤销权限、并发提交 | 后端拒绝；管理员全能力不突破禁止自审和原文不可变 |
| W04-11 | 数据集冻结、同周期变体、分井分时划分、后续资料撤销 | 固定成员/摘要可重放；无泄漏；撤销可见而历史不被重写 |
| W04-12 | 文件截断/错误摘要/错误分隔、断点重传、重复会话、恶意路径/文件名 | 服务器验证，不只信前端；没有伪造 MQTT 回执或文件执行 |
| W04-13 | 浏览器录波浏览/悬停/缺口/缩放、上传中断、切换时旧响应、不可用状态 | 两位小数只影响坐标显示；未发生无依据曲线填补或状态混淆 |
| W04-14 | 隔离环境迁移、最小数据库账号、备份恢复、重新导出 | 无 DDL/越权；字节与冻结摘要一致；恢复后不生成虚假新测量 |
| W04-15 | 现有全量回归及冻结版本保护核对 | v1/台账/WP-03/演示功能不回退，冻结目录/ZIP/标签不变 |

测试向量由确定性生成器和人工审阅的小样本构成：共时钟正常周期、已知延迟、漂移、丢点、削顶、错相序、反向位移、跨井、错误来源等。每个向量注明用途、生成算法/版本和预期结果；真实厂家测量与合成数据分目录、分来源保管。小型黄金向量可公开，大文件和私有证据不自动上传仓库。

容量验证记录机器配置、通道/采样率、每秒报文数、持续时间、峰值内存、处理延迟和实际存储增长；只报告实测范围，不预先宣称生产容量。测试依赖未启动时应报测试环境不就绪，不能把跳过集成测试写成全部通过。

验证继续使用用户已授权的隔离环境；新增 schema/角色/账号仅在核实隔离库身份并具备管理员授权的前提下创建。不得用业务库补齐测试条件。研发结束清理仅针对自己新建且已核实的临时资源；既有受保护或被环境拒绝清理的目录不碰。
