## 2 失败原因与已取得的有限证据

扩展输入 `cycle-variant-00` 在原生索引 198、时间 `99/64 s` 的平均功率包围约为 `[43827.044998472666, 43827.045005336615] W`，跨过精确半码边界 `8765409/200 W`。以 `0.01 W` 为编码步长，上下端点分别舍入为 4382704 和 4382705。区间宽度虽然符合编码前计算预算，仍不足以确定唯一原码；现有 `proof_rounding_ambiguous` 拒绝是正确行为。

只保留二阶余项的正负方向仍不能使生成端确定该原码。因此不采用这一单独改法，也不以校验端较窄的区间替换生成端自己的证明。增加分段、提高工作精度、筛掉该点、调整 seed 或减少工况均不属于本修订。

在未改动产品源码的内存探针中，选定公式得到：

| 计算路径 | 该点包围宽度约值 | 两端点的原码 |
| --- | ---: | --- |
| Cartesian 生成端 | `1.5750601386035504e-13 W` | 4382705 与 4382705 |
| polar/energy 独立校验端 | `6.136305933697593e-14 W` | 4382705 与 4382705 |

随后抽查 `cycle-base`、`cycle-variant-00`、`cycle-variant-39` 各 9 个索引：0、1、128、198、256、384、512、768、1024。27 对独立计算均可唯一编码、双方原码一致、区间有交集。探针只支持选定修复方向，不代表完整 44 正例、四故障场景、worker 期限或现场精度通过。正式实施必须将已知失败点转为可重复回归，并保存新的实测证据。

## 3 积分包围定义与证明

### 3.1 记号与适用条件

对于一个平均窗口，宽度 `w=1/1000 s`，固定分成 64 个等长闭子区间，`h=w/64`；第 i 个子区间为 `[a_i,b_i]`，中点为 `m_i`。`P(t,r)` 表示给定已注册机理参数、根参数 `r` 时的连续功率。`r` 在独立求得的根夹持区间内，整个窗口使用同一个实际根，不将其当作随时间变化的物理量。

对每个允许的 `r`，P 必须在每个完整子区间具有连续四阶导数。计算必须覆盖整个子区间和整个根夹持区间，且保证所用除法、平方根、反三角函数处于可解析域：分母不含零，需微分的平方根参数严格为正，反三角函数不跨分支或导数奇点。未能证明这些条件时拒绝；不能仅以中心点可计算作为依据。

### 3.2 中心修正和对称余项

三次 Taylor 展开在中点对称积分时，一阶和三阶项积分为零。因此：

`Q_i = h·P(m_i,r) + h³·P''(m_i,r)/24`

`|integral_[a_i,b_i] P(t,r)dt − Q_i| ≤ h⁵·B4_i/1920`

其中 `B4_i` 必须覆盖 `sup_(t,r)|∂⁴P(t,r)/∂t⁴|`，范围为完整子区间及允许的根区间；它是功率四阶导数界，不是原运动合同中的角度四阶界 M4。常数来自对称区间上 `|u|⁴/24` 的积分：`(1/24)·2·(h/2)⁵/5 = h⁵/1920`。这是本项目采用的 Taylor 余项推导，不把采样差或高低阶结果相近当作证明。

Arb 形式序列的系数为 `c_k=P^(k)/k!`。令 `C0_i` 和 `C2_i` 为中点的系数包围，`C4_i=[L4_i,U4_i]` 为整个子区间上的四阶系数包围，则实际计算为：

`T_i = h·C0_i + (h³/12)·C2_i`

`R_i = (h⁵/80)·max(|L4_i|,|U4_i|)`

`mean_interval = (Σ T_i + [−Σ R_i, Σ R_i]) / w`

T 中保留中点求值及二阶系数的全部区间误差；R 始终为非负对称半径，不把四阶导数符号用于缩小本次余项。即使四阶导数区间跨零，该式仍适用。不得把中点的 `c4` 当成完整子区间的上界。

允许使用 Arb 包围累加，或将包围端点导出为精确有理数后累加；每一步都须保留向外包围。h、w、阶乘和常数使用精确整数或 Fraction；系数取界和最终编码不经过 float、字符串显示值或截断小数。所有有理数输入、转换和中间算术继续执行 4096-bit 限制。把余项加回 Arb 时也不得丢掉转换误差。[Arb 区间端点接口](https://python-flint.readthedocs.io/en/stable/arb.html)

### 3.3 序列阶数和上下文

当前两套物理公式都包含一次序列求导，输入截断上限 4 只足以保留功率到二阶。修改时，两个功率状态计算入口都显式使用 `arb_series(..., prec=6)`，在受锁保护的证明上下文中将 `ctx.cap` 临时设为 6，并在正常或异常退出时恢复原值。生成端的固定 96 次根夹持、服务端的独立解析根判别及各自精度要求维持原实现，不进行全仓库 `prec=4` 文本替换。

`series.prec` 指序列项精度，与 `ctx.prec` 的系数工作精度不是同一项。[python-flint 序列接口](https://python-flint.readthedocs.io/en/stable/arb_series.html#flint.arb_series.prec)

使用功率四阶项之前必须检查最终 `power.prec > 4`，所需系数有限；不能依赖缺失高阶项默认返回零。中点修正至少检查 c0/c2，完整子区间至少检查 c4；其他状态输出的原检查不删减。固定 128-bit、单线程和原运行时锁保持不变。

### 3.4 平均和瞬时功率仍须分账

生成端继续分别输出平均功率和瞬时功率；位移、载荷及角度计算的物理定义不变。校验端继续由新平均包围减去独立瞬时包围，计算平均与瞬时语义差的最大绝对界，并与已声明预算比较。不能将更小的积分余项误当成全部功率输入误差，也不能忽略窗口平均与瞬时量的差异。

## 4 双端实现与接口边界

| 组件 | 本次职责 | 必须保持的独立性 |
| --- | --- | --- |
| `tools/testpack/forward_v2.py` | 在原 `forward_enclosures` 路径实现新积分公式、序列阶数和严格取界 | 保持 Cartesian 圆交点及转矩模型，独立根夹持，不读取校验端结果 |
| `backend/inversion/coverage_sources.py` | 在原 `_expected` 路径独立实现公式，继续核对实际原码和声明预算 | 保持 polar/energy 物理推导，不导入生成端物理或积分实现 |
| `cycles_v2.py` 的既有生成路径 | 消费新的包围并按既有四通道规则编码 | 不新增特例、通道回绕或原码修补 |
| 原治理和求解路径 | 检查新源码指纹，重算输入依据、逐点预算及原指标 | 名义预测继续仅读实际功率和角度，不消费参考载荷/位移 |

两个积分实现允许共享既有 `interval_runtime` 的有理数和区间基础设施，但不新建两端共用的积分或物理 helper。本次不新增运行时模块；若实施确实需要改变这一边界，先修改设计和指纹清单，不能让依赖遗漏在审核摘要之外。

公开函数参数、返回对象、合同 schema、模型家族和 API 不变。继续使用 `beam_energy_balance/2`、`finite-input/1` 检查方法版本及各自精确内容摘要，不以版本字符串相同冒充安装制品相同。完整方法变更由源码、安装快照、包清单及人读依据追溯。

两端必须分别用自己得到的最终包围完成最近偶数编码。仅当上下端点的精确舍入原码相同且落在 signed i32 范围内，才接受该编码。两端原码一致、区间相交只是交叉核验，不替代任何一端的包围证明。真正的边界歧义继续返回 `proof_rounding_ambiguous`；不添加浮点或旧公式回退路径。

本修订继承原设计第 3 节和原计划 Global Constraints 全部数值。以下列出与本修改直接相关的硬约束，未列出的约束不因此取消。

| 项目 | 固定要求 |
| --- | --- |
| 计算环境 | CPython 3.13.2、python-flint 0.9.0、FLINT 3.6.0；原锁定 wheel、ABI、许可及原生依赖摘要 |
| 证明计算 | 128-bit、单线程、64 子区间；Fraction 分子/分母及中间量不超过 4096 bit |
| 原生输入 | 每周期 8 秒、128 Hz、1025 帧；原 seed、参数变体和噪声/缺样/削顶/时移规则不变 |
| 四通道步长 | 功率 0.01 W；角度 1e-8 rad；载荷 0.001 kN；位移 1e-6 m；offset 均为 0 |
| 编码前声明 | 功率 0.01 W、角度 1e-20 rad；原 0.02 W 损耗界不变。不得因积分变窄而缩小这些安装最小声明 |
| 物理和数值预算 | 基础速度 1e-5 rad/s；物理分子 100 N·m、因子 1e-4 m；数值分子 0.01 N·m、因子/位移 1e-7 m；逐点载荷误差 1000 N |
| 通过指标 | 原始预测覆盖和共同比较支撑覆盖分别 ≥0.80；原始共同有效支撑 RMSE 非空且 ≤500 N |
| 缓存和求值 | 原权重/证明/轨迹/根缓存界不增大；每 case 物理区间求值上限 524288；缓存命中仍按原校验政策计费 |
| 执行和容量 | 总期限 180 秒、一个执行槽、16 个等待请求；输入 64 MiB、结果 16 MiB、每运行预留 80 MiB；其他附件/API/原文上限继承原计划 |

每个普通原生点的物理求值仍为 `1+2×64=129`：中心状态一次、每子区间中点与整段各一次。每条 1025 帧物理轨迹为 132225 次；独立校验时的移位场景继续额外计费，不能借缓存绕过上限。根求解及原缓存另按既有固定规则保持，129 不宣称包含全部根隔离运算。

高阶序列增加每次求值的运算成本，因此求值数量不变不证明时间或内存不变。正式 worker 必须重新实测；超时即失败，不提高 180 秒期限。区间宽度仍保留原功率不超过 0.02 W、角度不超过 2e-20 rad 的检查，并另行检查唯一编码。

## 6 版本封存和发布策略

源码提交后必须产生新的 checker/generator 摘要、新安装快照和新 pack ID。原 `checker_sha256`、`generator_sources_v2`、`deliver_v2` 源集合、`model_manifest_v2.SOURCE_FILES` 及导出白名单必须覆盖实际改变的文件；定向测试检查这些闭包，不能只断言某个版本字符串没变。v1 指纹函数本身不改，旧包按其已保存的身份读取，不要求今天重新计算的全工具目录摘要等于历史摘要。

已有模型登记不能在同一数据库中用同一个 model key 覆盖；旧批准快照与新代码不同应继续触发 `artifact_changed`。本次只在新建、带所有权清单的隔离发布目录和新 lab 中安装、登记和重新审批。不新增原位迁移，也不复制旧批准事件充当新模型审批。

原演示服务、旧阅读器、封存软件、旧测试包与验收资料保持不变。已有 smoke-r4 的成功结论继续限定于其源码和范围；失败的 extended-r1 原目录、日志及 `preparing` 状态留存，不覆盖为成功，也不作为新尝试的输出目录。新尝试使用新的目录和身份，空闲端口及所属进程必须在执行时核对。

只读历史结果与“当前新安装可定量执行”分开判断。回退仅禁用本轮新运行并停用本轮所属 worker/实例，保留原文、结果、审计和失败记录。不会为了清除失败状态删除数据库。远端推送不在本修订授权范围内。
