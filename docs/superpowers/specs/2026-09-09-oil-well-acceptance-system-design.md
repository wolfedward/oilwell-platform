# 油井智能化抽油测控平台验收版设计说明

日期：2026-09-09  
适用范围：第一年度（2024-06—2025-06）与第二年度（2025-06—2026-06）阶段性正式验收

## 1. 建设目标

将现有静态页面 demo 改造成可在本机离线运行、能够现场操作、数据前后一致、关键业务可追溯的验收系统。系统需要覆盖任务书中油井数字智能化自动化管理、低产井节能控制以及 DSP+MCU 智能测控单元相关工作，并支持评审人员自由点查关键页面。

本系统定位为软件与算法的集成测试平台。没有连接现场实物设备时，由虚拟 DSP+MCU 终端提供符合接口约定的采集报文、设备状态和控制回执。界面使用正常业务名称，不放置“演示系统”或“演示数据”水印；数据库仍保存数据源类型、生成时间和设备标识，以保证技术可追溯性。现场不得将虚拟设备生成的数据表述为实际井场采集记录。

## 2. 当前系统问题

现有版本包含大量菜单，但多数页面由少量通用模板生成，数据为前端即时构造。除导航和标签切换外，查询、保存、审批、下发、导出、工单流转等按钮缺少完整业务行为。系统没有后端数据库、设备通信状态机、权限、审计和重启恢复能力，无法支持正式验收中的操作检查和技术追问。

## 3. 技术路线

### 3.1 总体架构

系统采用单机离线三层架构：

1. 浏览器前端：HTML、CSS、原生 JavaScript，负责业务页面、图表和操作交互。
2. 本地业务服务：Python 3.13 标准库实现 HTTP API、业务校验、算法执行、报表输出和虚拟设备调度。
3. SQLite 数据库：保存基础档案、时序数据、分析结果、策略、工单、报表和审计记录。

虚拟测控终端作为本地业务服务的受控后台任务运行，定时写入心跳、遥测和功图采样，并消费待下发命令。系统不依赖外网、云服务或现场硬件。

### 3.2 选择理由

- 验收电脑已安装 Python 3.13、Chrome 和 Edge，无需下载运行时。
- Python 标准库与 SQLite 无额外服务依赖，便于一键启动和故障恢复。
- 前后端通过明确 API 分离，后续可替换成真实设备接口或企业数据库。
- SQLite 数据文件便于备份、初始化和验收后留档。

## 4. 年度任务映射

### 4.1 第一年度

#### 油井数据采集传输管理系统

- 虚拟终端、采集通道、心跳、在线/离线和通信质量管理。
- 电流、电压、功率、位移、载荷、冲次等数据采集。
- 完整性检查、范围检查、离群识别、重复数据识别和缺测标记。
- 断点续传、失败重试、原始报文留存和处理日志。
- 数据订阅、查询、CSV 导出和数据质量统计。

#### 油井数字化监测与智能诊断系统

- 原始电功图、电参曲线和转换后示功图展示。
- 周期识别、滤波、转矩换算、平衡修正和位移—载荷转换。
- 最大/最小载荷、功图面积、充满度、上下冲程差异和畸变特征提取。
- 正常、供液不足、间歇供液、泵漏、空抽风险等工况诊断。
- 诊断置信度、判断依据、标准功图对比、历史变化和人工复核。
- 理论排量、泵效和估算产液量计算。

#### 油井智能决策支持系统

- 诊断结果自动分级并生成处置建议。
- 告警确认、策略推荐、审批、指令下发和执行反馈。
- 告警、诊断、策略、设备指令和工单之间可双向追溯。
- 超时督办、人工接管、关闭结论和效果复核。

### 4.2 第二年度

#### 产油井节能控制系统

- 低产井筛选、供液能力和停机恢复特性分析。
- 渗流恢复时间常数、最低开机时长、最高停机时长、最低产量等约束配置。
- 多组开停机周期试算与产量、耗电、运行时间对比。
- 策略创建、审批、下发、暂停、回退和版本管理。
- 策略实施前后耗电量、运行时长、产液量和节能率评价。

#### 智能化抽油测控系统

- DSP、MCU、通信模块、固件版本、采集通道和设备参数档案。
- 心跳、实时寄存器、运行模式、通信报文和设备自检。
- 远程参数配置、启停控制、命令校验、回执、超时和重试。
- 离线保护、越限保护、通信中断时的本地策略和人工接管。
- 故障、升级、维护及操作审计记录。

## 5. 页面信息架构

### 5.1 首页

项目总览、产量、开井率、设备在线率、数据完整率、待处置告警、待审批策略、当日耗电和累计节能量。指标卡可以跳转到对应业务明细。

### 5.2 生产监控

油井台账、单井运行总览、实时数据、历史趋势、生产状态维护和井场分布。单井详情作为业务枢纽，关联设备、功图、诊断、策略、告警和工单。

### 5.3 功图智能

电功图采集、转换分析、功图数据、特征提取、智能诊断、产液量计算、标准功图库、模型运行记录和人工复核。

### 5.4 采集传输

采集任务、实时数据流、原始报文、清洗记录、异常数据、质量分析、断点续传、数据共享和传输日志。

### 5.5 节能控制

节能总览、低产井识别、恢复曲线、周期优化、策略中心、策略审批、执行监控、失败回退和效果评价。

### 5.6 协同处置

报警中心、诊断工单、节能策略工单、审批中心、超时督办和闭环台账。

### 5.7 设备运维

测控终端、采集通道、实时寄存器、通信报文、远程控制、固件版本、设备故障和维护记录。

### 5.8 报表分析

生产日报、功图诊断、数据质量、策略执行、节能效果和工单闭环报表，支持筛选、打印和 CSV 导出。

### 5.9 系统管理

用户、角色、数据权限、参数字典、模型版本、操作审计、系统日志、任务书功能映射和验收证据索引。

## 6. 数据设计

### 6.1 初始化规模

- 4 个采油单元、8 个井组、48 口抽油机井。
- 48 台虚拟测控终端，约 16 口井具有低产或间抽特征。
- 不少于 90 天的日生产记录。
- 不少于 30 天的小时级遥测，并保留最近 24 小时的高频变化样本。
- 每口井包含功图记录、诊断记录、设备事件和质量统计。
- 系统预置不同状态的告警、策略、审批和工单，以便检查状态流转。

初始化数据使用固定随机种子和井档案参数生成。同一口井的产量、功率、泵效、功图面积、设备状态和诊断结果保持关联；刷新页面不会改变历史值。虚拟终端启动后按模拟时钟继续追加新记录。

### 6.2 核心数据表

- `units`、`well_groups`、`wells`：组织、井组和单井档案。
- `devices`、`device_channels`、`device_heartbeats`：终端及运行状态。
- `telemetry`、`raw_messages`、`data_quality_events`：遥测、报文和质量事件。
- `dynagraphs`、`dynagraph_features`、`diagnoses`、`model_runs`：功图与算法结果。
- `recovery_tests`、`energy_strategies`、`strategy_versions`：恢复试验和节能策略。
- `device_commands`、`command_attempts`：命令及每次执行尝试。
- `alarms`、`approvals`、`work_orders`、`work_order_logs`：业务闭环。
- `reports`、`users`、`roles`、`audit_logs`、`system_events`：报表、权限和审计。

所有关键业务表包含创建时间、更新时间、业务状态、操作人和关联对象标识。

## 7. 算法与可解释性

### 7.1 电功图到示功图转换

输入为按一个冲程周期采样的电流、电压、功率、相位或功率因数以及机构参数。处理步骤为：

1. 异常采样剔除和移动窗口平滑。
2. 按冲次与波形极值完成周期分割和相位归一化。
3. 由电功率和角速度估算电机输出转矩。
4. 结合传动比、机械效率、平衡力矩和结构参数换算悬点载荷。
5. 由曲柄角与四连杆几何关系计算悬点位移。
6. 输出位移—载荷闭合曲线及转换参数。

页面同时显示输入曲线、中间参数、转换结果和算法日志，允许调整校正系数后重新计算。

### 7.2 特征与诊断

提取最大载荷、最小载荷、面积、充满度、上下冲程载荷差、拐点数量、曲线闭合度和模板距离。诊断采用可解释的混合方法：工程规则先排除越限和机械故障，再以归一化特征距离匹配典型功图库。结果包含候选工况、置信度、触发规则、相似样本和处置建议。

### 7.3 产液量估算

根据泵径、有效冲程、冲次计算理论排量，再使用充满系数、泵效和单井校正系数得到估算产液量。页面展示各输入项、计算步骤和校正记录，避免只给出不可解释的最终值。

### 7.4 节能周期优化

使用指数恢复曲线描述停机后的供液恢复：恢复量随停机时间增长并逐渐趋于稳定。算法在最低开机时长、最高停机时长、最小日产液量、最大启停次数和设备保护限制内枚举候选周期，计算每个方案的预计产量、耗电、运行时间和节能率，按满足产量约束后的最低耗电排序。评审可修改约束并立即重新试算。

## 8. 业务状态与数据流

### 8.1 主验收闭环

1. 虚拟终端产生电参和功图采样。
2. 采集服务校验报文并写入原始数据区。
3. 清洗任务生成可用遥测和质量事件。
4. 功图服务完成转换、特征提取和工况诊断。
5. 异常诊断生成告警与策略建议。
6. 工程师确认建议并创建节能策略。
7. 策略通过审批后生成设备命令。
8. 虚拟终端校验并执行命令，返回分阶段回执。
9. 系统更新单井状态并建立跟踪工单。
10. 运行数据进入效果评价，形成报表和闭环记录。

### 8.2 状态机

- 告警：新建 → 已确认 → 已派发 → 处理中 → 已关闭；可进入误报关闭或升级督办。
- 策略：草稿 → 待审批 → 已批准 → 待下发 → 执行中 → 已生效；可被拒绝、暂停、失败或回退。
- 命令：待发送 → 已发送 → 已接收 → 已校验 → 执行中 → 成功；异常可进入重试、失败或取消。
- 工单：待接单 → 已接单 → 处理中 → 待复核 → 已关闭；超时状态独立记录。

每次状态变化均写入业务日志和审计日志。

## 9. 异常处理与安全控制

- 终端离线时命令进入等待队列，上线后按有效期重新下发。
- 报文校验失败时拒绝入业务数据区，保留原始报文和失败原因。
- 采集缺口触发补传任务，补传前后的完整率均可查询。
- 命令超时按配置重试；超过次数后转人工处理并产生告警。
- 冲次、开停时长、电流和功率等参数执行安全范围校验。
- 策略版本发布后不可原地修改，只能建立新版本或回退。
- 审计日志在业务界面只读，记录登录、修改、审批、控制和导出行为。
- API 对输入类型、对象存在性、状态转换和权限进行服务端校验。

## 10. 用户与权限

预置管理员、生产工程师、算法工程师、设备运维和只读评审五类角色。管理员可配置基础数据；生产工程师可确认告警和提交策略；算法工程师可运行模型并复核诊断；设备运维可下发设备参数和处理故障；只读评审可查看全部数据和报表但不能改变状态。

系统采用本地登录会话。验收环境提供明确的账号切换入口，避免依赖外部统一身份系统。

## 11. 报表与导出

报表由后端根据当前数据库实时计算。CSV 导出包含筛选条件、生成时间和明细数据；浏览器打印视图提供标题、统计口径和页脚。关键报表包括：生产日报、功图诊断、数据质量、策略执行、节能效果和工单闭环。

## 12. 验收演示脚本

主流程控制在 15—20 分钟：

1. 登录并查看首页指标。
2. 打开指定油井和对应虚拟终端，观察心跳和通信报文。
3. 触发供液不足测试场景并观察数据进入采集链路。
4. 展示电功图转换、特征提取、诊断依据和产液量估算。
5. 查看自动告警与处置建议。
6. 打开恢复曲线，调整约束并对比候选开停方案。
7. 创建策略、完成审批并下发设备命令。
8. 查看终端回执、单井状态变化和工单进度。
9. 展示策略前后指标与节能效果报表。
10. 在验收中心追溯本次操作产生的全部记录。

备用演示包括终端离线后补发、数据缺口补传、参数越限拦截和策略回退。

## 13. 验证要求

- 算法单元测试：滤波、特征、诊断、产液量和周期优化的确定性结果。
- API 测试：查询、写入、校验、权限、导出和错误响应。
- 状态流转测试：告警、策略、命令和工单的合法及非法转换。
- 数据一致性测试：关联记录、统计指标和报表汇总一致。
- 重启恢复测试：关闭并重新启动服务后业务状态和历史数据不丢失。
- 浏览器测试：Chrome 与 Edge 的核心页面和主验收闭环。
- 一键启动测试：启动服务、检查端口、打开页面和生成日志。
- 离线测试：断开外网后系统全部核心功能仍可使用。
