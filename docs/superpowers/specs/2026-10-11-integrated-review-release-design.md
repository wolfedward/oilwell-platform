# 年度任务软件集成与本机审查部署设计

## 目标与授权

用户于 2026-10-11 要求“把剩余开发工作全做完，然后部署，我审查再修改”。本轮连续实施、完成后供用户审查，不再逐项请求设计/计划确认；该指令不授权伪造现场证据、改变冻结演示版、开放公网或驱动实际设备。基线为 `9443e8519101789d38ac82788cc98d6c1ae65225`。仅实现年度工作任务，绩效目标不在范围。

交付对象是这台电脑上的独立软件审查部署，以及可复用的算法、接口、测试和运维工具。没有硬件、标定和实测数据时，硬件实物、现场精度/节能率/保护认证和长期稳定性仍是外部验收项；不得将软件交付称为所有年度现场工作已完成。

## 选定架构

保留已实现的 PostgreSQL 生产台账、可靠接收、同步波形、反演服务及其最小权限边界。新增 `backend/studies/` 工程分析模块，使用平台既有 SQLite 身份库中的独立 `study_*` 表保存不可覆盖的输入、运行结果、人工复核、选用历史与审计；这是单机审查/低并发工程分析，不冒称分布式遥测数据库。计算不在 SQLite 写事务中执行，有限输入、显式算法版本、当前鉴权和原请求幂等重试贯穿流程。

选择这一方案是为了复用已验证的身份/审计与真实计算，并保持 PostgreSQL 原始资料的生产权限不变。另一方案是把新增分析直接并入旧模拟策略表，会混淆来源和控制资格，故不采用；全面替换平台技术栈会造成无必要迁移，亦不采用。

新模块页面共用现有登录和导航，但生产审查模式不自动生成旧演示井、不启动模拟终端、不允许旧演示控制写入口。人工上传是“提交的观测资料”，有来源声明和摘要，不因上传成功/人工批准自动变成现场测量或定量控制资格。用于页面演练的软件向量必须单独显式载入，来源不可更改为实测。

## 全局约束

- 原工作目录、冻结演示目录/ZIP/tag、既有业务库与测试库不修改；开发仅在当前独立工作区。
- 本机部署仅绑定 `127.0.0.1`，审查 HTTP 首选 `8770`，新 PostgreSQL 首选 `55432`；端口占用则拒绝，不结束未知进程。
- 无实际设备控制：`control_enabled=false`；不新增 Modbus 写寄存器或 MQTT 下行执行，不以网页/网络代码代替硬件保护。
- 新数据保留明确来源、单位、时间、质量与内容摘要；软件向量不能被批准为现场证据；缺信息给出拒绝/未知，不填补虚假默认值。
- 新工程分析 API 最大 JSON 输入 `8 MiB`，拒绝重复键、非有限数、布尔冒充数值、未知字段及越界样本；列表每页最多 `100`。
- 同身份库写入、审计、幂等回执在 `BEGIN IMMEDIATE` 事务中一起提交，并在该事务中复核当前会话/权限；计算在事务外，提交前复核。
- 新分析只产生建议、研究结果和影子策略。审批者不能复核自己的成果；历史输入/结果不覆盖，撤销与选用以追加事件表达。
- 算法只有显式受支持的版本；不加载用户提供的 pickle、动态 Python 或可执行模型；机器学习制品为有界数值 JSON。
- 按已确认的分层验证执行：每项针对性测试、独立审查，关键集成点再组合回归。不得将历史混合源码回归说成新版本一次全绿。
- 所有未解决问题、软件/现场边界和部署回退步骤在交付记录中列明；测试与私有部署凭据不公开上传。

## A. 反演收尾（WP05A）

1. 完整展示后端允许的每一个拒绝原因，含原因代码及可操作的核查方向；未知原因显式显示“未知原因”及安全截断代码，不能假装已识别。原状态/覆盖率判断不变。
2. 中间功率、角度、驱动转矩按各自有限值显示。预测死点处仍可读其已保存数值，但不把数值存在等同于可信区间；缺口不连线，主载荷、比较指标、原始结果字节与旧结果不改写。
3. 整理参数/表单状态转换的密集代码，保持幂等恢复、撤权、切换和销毁行为；不顺便重写求解器。

## B. 工程分析治理（WP05B / WP08）

记录类型为 `condition_training`、`condition_prediction`、`recovery_fit`、`energy_schedule`、`motor_spectrum`、`protection_replay`。每个运行固定 kind、schema、algorithm_version、input_sha256、actor、created_at、source_kind、result_sha256；有限结果与原始输入可审计导出。每次提交带 UUID `request_id`；同人同键同内容返回原记录，同键不同内容返回冲突。提交后断网重试必须保留原键和原文。

运行和复核分开：`completed` 表示软件完成计算，不表示结论已通过现场验证；结果可为 `insufficient_evidence`/`not_applicable`/`no_feasible_schedule`。复核追加 `approved`/`rejected`/`revoked` 与意见。模型/策略的影子选用指向已批准记录，回退追加选用事件，预测时重新核对选用及复核。展示历史时同时显示当前限制。

来源声明为 `software_fixture` 或 `submitted_observation`，后者需要非空来源说明和原始资料引用；不提供 `field_verified=true` 的人工开关。第一版输入可从严格 JSON 资料导入；从已部署 WP04 的规范导出取得的资料保持原摘要/引用并校验，不自动读取私有文件路径。

## C. 工况模型（WP05B）

以显式标注的数据集运行同一测试集的规则基线、最近类中心统计基线和真实反向传播单隐层分类器。数据按井分组并按时间外推划分；训练/验证/测试的周期与井不能泄漏，缩放只由训练集拟合。明确报告每类数量、混淆矩阵、宏平均 F1、拒识率、超训练范围比例，不能只报准确率。

受支持的模型是受限数值网络，不支持执行任意上传模型。训练有固定种子、最大样本/特征/隐层/轮次/运算预算，失败不保存假模型；输出参数与训练曲线可复现。无真实数据时只能训练软件向量验证管线，不能声称已具备真实工况识别能力。预测低置信度或训练范围外返回未知，不驱动控制。

## D. 恢复试验和影子优化（WP06）

直接液面/压力恢复资料与“关井时长—复开产液率”是不同观测，禁止互换单位。新增具单位和质量的恢复观测契约，显式选定一阶经验模型，报告基线、幅度、时间常数、残差、拟合支持范围和不确定性；平坦/反向/缺口/不足数据拒绝。经验拟合不是油藏压力瞬态解释。

采用有限时域离散开停计划，输入设备的最小开停时长、起始状态及已持续时间、每日启停数、泵能力、功率、最低产液和最大并发功率等显式约束。逐时间段核对库存/供液、容量、启停、功率；无可行解明确返回，不突破约束“优化”。仅给模型预测和影子建议，不把模拟电量差当实测节能。支持上传实际观测与候选计划比较，注明覆盖不足及不可比条件。

## E. 电机频谱、保护与开放边缘参考（WP07 / WP08）

录波要求采样率、样本时间、单位/校准、抗混叠、稳态、供电频率、电机极数和转速依据。去直流、Hann 窗和经幅值校正的单边频谱计算主频与 `(1±2s)f` 候选边带，报告频率分辨率和滑差。缺转速/分辨率不足/非稳态/削顶/缺样时不输出确定性断条结论；即使出现边带也只能“可疑特征”，因为周期负载等可混淆。

保护软件由显式整定驱动：过欠压、过流、相不平衡、温度、缺测/陈旧等按持续时间、迟滞、闭锁复位运行可重放状态机。阈值必须来自提交的整定依据，本系统不编造通用安全阈值。状态机在软件重放及厂商参考中使用；没有电机保护认证，没有物理接触器输出。

公开参考给出 DSP 同步采样/特征计算与 MCU 通信/看门狗/状态机分工、版本握手、质量与故障上报、断网失效安全、硬联锁优先和测试向量。模块图是开放设计参考，不冒称可直接生产的认证 PCB 或硬件成品。

## F. UI、部署与验收

提供工程总览、模型试验、恢复/影子优化、电机频谱/保护、记录复核页面。输入使用具单位表单/文件选择与可检查示例，不仅是一个 JSON 文本框；显示计算图、指标、原因、来源和历史。所有二维图默认细线，悬停/键盘显示两位小数，不因格式化改变保存值；加载/空/拒绝/权限/不可用状态分开。

新增显式初始化与部署工具：空身份库、安全随机初始密码、版本标识、备份检查、新 PostgreSQL 数据目录/账号/迁移、仅本机访问、服务归属记录、启动健康检查、停止及回退指令。不能调用硬编码旧测试库的 provision 工具。应用启动只检查已准备结构，不种演示数据、不做隐式生产提权；现有演示启动行为向后兼容。

部署产物固定本轮源码清单；新端口打开并验证登录、各模块实际 HTTP/持久化、拒绝路径、审计/导出、重启后历史仍在，以及备份恢复到新目标。原演示/既有服务不受影响。交付 URL、账号取得方式、版本、验证摘要及明确未完成的现场项。
