# WP-02 实施裁定（按实际作出顺序）

这些是实施时在不改变批准范围的前提下解决计划矛盾、接口歧义与验证条件的记录，不是新功能清单。完整执行记录保留于 `logs/registry-wp02/task-history/progress.md`；原始进度文件开头插入了 Task 8 的预检裁定，本文依实际时间排序，而非其文件行号排序。

| 顺序 | 裁定与原因 | 代价或边界 |
| --- | --- | --- |
| 1 | 点表协议由已登记设备决定，不信任客户端另报协议 | 不匹配的点表被拒绝 |
| 2 | 目录服务从首次实现就支持引用加锁，保证取数据库时间晚于所需锁 | 增加锁查询 |
| 3 | 缺失模块的 RED 测试使用受保护导入及明确断言 | 失败消息更长 |
| 4 | 公共值校验放入独立 values 模块，避免循环依赖 | 多一个内部模块 |
| 5 | JSON 嵌套上限 64 层，限制异常输入开销 | 超深、未支持请求被拒绝 |
| 6 | 迁移摘要统一换行为 LF，兼容 Windows 检出 | 只改换行不会触发摘要差异，SQL 语义修改仍可检测 |
| 7 | 开放时段仅使用 NULL，不接受数据库 infinity 时间值 | 旧的非约定无限时间导入被拒绝 |
| 8 | 独立只读 check_schema，检查不能复用执行迁移的路径 | 增加内部接口；不替代运行权限检查 |
| 9 | 经授权的测试环境放在原项目忽略目录 data/registry-test，避免工作区清理丢失 | 原项目多一个独立测试目录，不覆盖既有文件 |
| 10 | 中间全量回归可按不相交模块分两组，最终全量仍串行 | 中间进程顺序不同；以最终串行补足验证 |
| 11 | 生命周期写入在取时间前锁定开放历史行，防止直接写库造成时间竞争 | 每次低频管理操作增加三次索引查询/锁 |
| 12 | 内部设备 UUID 与网关/终端上行标识分开，分页输入 revision 对应输出 registry_revision | 接口调用方必须显式转换和保留上下文 |
| 13 | 原始记录翻页额外携带 query_total，迟到提交改变集合时要求刷新 | 客户端多传一个字段，并可能重查 |
| 14 | 只读权限预检独立为 privileges 模块，通过 runtime 延迟加载 | 多一个内部模块 |
| 15 | 状态时限不超过一天，避免大阈值掩盖失联 | 极慢上报场景需重新确认时限政策 |
| 16 | 预检覆盖原始分区及 session_replication_role 授权，排查绕过保护的能力 | 持有未使用高权限的账号也会被拒绝 |
| 17 | 未配置统一为 disabled / registry.disabled，解决计划内部命名不一致 | 对接方需按最终契约使用该状态 |
| 18 | 服务对象统一挂在 server.registry_runtime，避免别名导致静默禁用 | 后续调用方必须沿用该名称 |
| 19 | 响应式只改台账局部，不改旧页面全局 1180px 最小宽度 | 小屏外壳仍可能横向滚动 |
| 20 | 旧版本迁移测试先停后台写入，再构造旧摘要，避免测试自身竞争 | 该构造阶段不再并发；生产行为未改，另有并发测试 |
| 21 | 补改计划漏列的 acquisition.js，转发来源核查导航 | 多触及一个旧页面入口，仅增加可选参数 |
| 22 | 能力开关同时接到现有前端入口，完成禁用导航/直接路由说明 | 增加前端回归范围；展示开关不替代鉴权 |
| 23 | 默认端口按浏览器省略 80/443，替代计划中必须显式端口的假设 | 归一化错误可能误拒绝/误信任来源，因此覆盖匹配与拒绝测试 |
| 24 | 正式部署、实物和真实效果仍未验证，不由隔离测试推定完成 | 环境兼容性与现场效果留待受控部署/调试 |
| 25 | 对审查未覆盖的小屏外壳再次确认维持原边界 | 窄屏用户仍可能需要横向滚动 |
| 26 | 数据库管理员是信任边界，不可变历史不承诺抵御恶意超级用户 | 管理员被攻破仍可改写数据，不是密码学防篡改 |
| 27 | 收尾按已批准的“不推送、不建 PR”范围保留独立工作区，不再要求重复选择推送选项 | 现有网页不会自动更新，合并/部署须另行确认 |
| 28 | 环境策略拒绝临时目录删除，因此保留，不换命令绕过；验证记录另行归档 | 忽略的临时文件仍占磁盘空间，未发生删除 |

默认端口裁定依据 [WHATWG URL 标准](https://url.spec.whatwg.org/#port-state)。审查没有发现需延期的 Minor 项；三个 Important 均已在一次修复轮次中先复现再修复，最终全量结果见审查记录。
