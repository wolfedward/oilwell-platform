# WP05A 功图反演部署与回退

本交付是生产反演的软件能力，默认关闭，尚未合并、部署或现场验收。专项、历史回归和最终当前源码回归分别记录；最终 `report.json` 与 `source.json` 固定源码清单、逐例名称/耗时/结果、发现分母、安全状态和清理归属。整体分支审查及原环境恢复由协调任务另行完成。

## 输入与适用范围

首版只支持常规曲柄平衡、刚性四连杆、圆弧驴头和工频异步电机端总有功。保留负功率，不支持 VFD 前端、直流母线或六路电压电流合成功率。必需角色是 `active_power`、`crank_angle`、`load`、`displacement`；功率为中心时间戳的 `window_mean`，其他为瞬时量。预测只用功率和角度，参考载荷/位移随后比较。不补默认尺寸、静载、损耗或不确定度，不调用旧演示算法。

参数为 `inversion.parameter-set/1`，算法/模型为 `beam_energy_balance/1`，输入为 `inversion.input/1`。几何分支按 `cross(P-B,R-B)`，曲柄矩以曲柄向上为参考，游梁局部 +x 指后臂；拒绝绕转/非摇杆几何。

厂家须提供采样边界、单位、平均窗、同步、标定和安装依据。完整周期要求良好连续原始角度样本支持精确起止边界，整圈角跨度满足经批准的一致性界；不自动重建边界。原始索引/时间保持整数或有理数精度，校正只应用一次。`CalibrationCycle.start_ns/end_ns` 是绝对 UTC Unix 纳秒；旧记录的模糊相对偏移须补充锚定后继证据，不能默默重解释。

参数、机械、采样和校准来源标签在本版严格一致；不同组织可由真实装配依据关联，不能改标签绕过限制。软件身份 `test:<name>` 与真实井 UUID 分离；已批准 synthetic 快照可有 `registry.well=null`，元数据保留测试指派而物理 `well_id=null`。

## 显式安装

1. 部署负责人先核对目标集群/数据库身份、备份、恢复方案和服务归属。开发测试配置、重置和 provision 工具不能用于生产。
2. 按 [WP04 部署说明](同步波形部署与回退.md) 安装完整 WP04 迁移，含 `006` 依赖保护和 registry 历史投影；registry 所有者执行 `grant_registry_history_prerequisites`，不得提升接收账号代替所有者。
3. 维护流程显式调用 `backend.inversion.migrate.migrate(settings, expected_database=..., limits=...)` 安装 `001`—`005`，`005` 增加审计请求查询索引。owner/reader/operator 分离且无超级权限/成员继承；owner 所需数据库 CREATE 仅在授权安装窗口存在，之后撤销。旧迁移不可覆盖改写。
4. inversion owner 执行 `grant_roles`；waveform owner 执行 `backend.inversion.metadata.grant_metadata`；独立 registry owner 执行 `grant_registry_metadata`。运行者只得到精确元数据列和业务锁函数权限，不能读取附件 payload 或执行 DDL。
5. 以 [默认禁用示例](../config/inversion.example.toml) 建部署私有配置，引用完整 WP04 management 配置、计费桶、独立 reader/operator、平台现有同一 SQLite 身份文件和预先存在的私有暂存目录。凭据通过已有环境引用/系统凭据存储提供，不进入 HTTP、公开示例或报告。
6. 平台启动显式传 `--inversion-config <private-path>`；生产启用需另行授权。启动只读验证 schema/授权/容量/身份，不自动 DDL、不启动 worker、不回退到演示数据。身份文件缺失/不可读、会话撤销和权限漂移均关闭对应能力。
7. 服务管理者独立启动 `python -m backend.inversion worker --config <private-path>`，记录 PID、启动时间、配置和所有者。核对 `/api/production-inversion/health`、`/api/auth/me` 的 `production_inversion`、缺失权限、槽位和容量；ready 不代表现场准确。

本轮运行兼容性范围为 Windows、CPython 3.13.2 和 PostgreSQL 18 隔离实例。局部进程适配器处理 Windows spawn 原生子进程已创建但序列化失败的归属；升级运行时后需重新做真实启动、部分启动失败和后代回收冒烟，不能宣称未验证平台可移植。

## 审批、输出和取消

依次建立来源/采样/校准/同步证据、合格 pair、冻结成员、参数编制与另一用户独立审批、已安装制品审核和明确 selection。purpose/source 附件 pin 不虚构审批版本；覆盖批准是人工审阅依据，不是软件证明文档真实。物理配置/井指派的有效结束用追加历史表达，原声明不可变；实际样本含两端，末端加不确定度必须严格早于排除性的 valid_to。

运行固定输入/参数/模型/审批/selection/工况 pins，worker 再次授权和取得真实原文。请求幂等摘要与后续完整 InputSnapshot 摘要不同。回复丢失时用原动作、key、完整请求查询 `/requests/{key}`；unknown 不证明未提交，不自动换 key。导出恢复须带原 intent。结果复核者不能是运行作者或快照作者，管理员也不能自我复核。

图表有效段断开，完整分页保留原索引/时间；m/kN 是显示换算，内部载荷与指标仍为 N。参考自身支撑与联合比较有效性分开；补绘为独立 display-only 输出，默认关闭，不能提高主覆盖或验收。执行、来源、当前用途、人工复核、现场验证分别呈现。

依赖撤销后历史正文/摘要不变，定量用途变为 restricted；有权限时可走标记 evidence 的审计导出。定量导出需要当前适用且独立复核批准，首字节前重验权限/依赖并提交审计。队列取消立即终态；运行 cancel_requested 显示“正在取消”，先回收归属进程后释放槽/预留。过期 worker 由下一次受控 tick 恢复，没有自动重试。

## 预算与回退

| 限制 | 默认或上限 |
| --- | --- |
| 执行/等待 | 1 槽 / 16 请求 |
| 单请求 | 1 pair、最多 2 capture |
| 每 capture | 解码 16 MiB、原文 32 MiB |
| 每必需通道 | selection 最多 32768 样本 |
| 输入/结果暂存 | 64 MiB / 16 MiB |
| 请求政策 JSON | 256 KiB |
| 总截止/单次数据库操作/锁等待 | 180 秒 / 3 秒 / 1 秒 |
| 损耗网格 | 每轴 2—64 严增节点、最多 4096 值 |

运动拟合七点三次局部窗口，不跨缺口或周期外推。总容量为 `run_input_and_results` 加未结算预留，包含输入快照和结果；治理/审计元数据、索引、WAL、物理文件不在此逻辑预算内。部署必须独立监控磁盘增长、WAL、备份和剩余空间。

回退先停新运行入口，记录未终态请求，按现有取消/恢复流程回收明确归属 worker 及后代并核对槽/预留，再停用模块。保留 schema、冻结输入、结果、审批、审计；不删历史，不覆盖 WP04 或冻结演示包。

selection 回退是追加事件：目标旧参数/旧制品须仍受支持、可用、独立批准且政策兼容。回退不恢复旧 selection 版本号，历史结果仍可能 restricted。测试临时替代制品仅检验治理、回退及历史不改，不代表生产安装/执行第二个求解器。

## 证据和现场边界

[端到端验收](../tests/test_inversion_end_to_end.py) 从 synthetic 完整 WP04 文件经真实导入/证据/冻结、双用户参数审批、HTTP、生产 factory 的新进程、predict/compare/codec、独立复核和审计导出；不直接插入成功结果。向量为 129 点/64 Hz、1 ms 中心平均功率，经固定 16-panel Simpson 后量化并检查 8-panel 量化一致。这是低载荷/宽误差界的软件向量，与参考共享构造依据，不是厂家合格配置或独立现场数据；实际采集路径重新导出时间和来源 pin。

libm 一 ulp 包围是条件假设，不是 Python math 通用保证；QR 残差/条件数不能认证物理精度。物理损耗、窗平均、角度/时间、几何和未建模动力学须有批准依据。联合比较按原生中心时间积分支撑；周期缺支撑时整周期有符号地面功为 null，部分支撑功另列，不能称井下有效功、产量或效率。

验证入口为 `python -m tools.verify_inversion --config <isolated-private-path> --output <ignored-private-directory> --include-existing-regression`。私有 JSON 配置包含 `schema="inversion.verification/1"`、`security_baseline_path`、`security_baseline_sha256`。授权操作者在完整 fixture union 初始化并审阅后固定基线；工具只读核对，不能自动接受观察差异或修复授权。无 full 参数只声明 inversion 范围。

每次独占新报告目录，一次 discover 的具体唯一测试 IDs 为唯一分母。缺例、重复、跳过、预期失败、意外成功、loader 错误、源码变化、安全或清理证据缺失均不能通过。临时权限测试在 setUp 后/方法前和 finally 后/tearDown 前核对；外部父进程对正常或硬退出都重新做逐库身份/catalog 检查。漂移先停，按明确对象与捕获状态决定恢复，不能用下一 fixture 掩盖。后续文档修改也会使旧报告的“当前源码”声明失效。

仍需真实设备/标定、独立周期及跨井数据、误差预算、长期稳定性、生产备份恢复与安全验收。未完成现场精度、实际节能认证、BP 训练或自动控制；本工作包不是年度平台整体完成。

## 隔离环境混合恢复边界

`tools.waveform_restore.backup_restore(..., profile='wp05a')` 是显式、固定的隔离测试恢复配置，不是通用数据库克隆或生产恢复入口。默认 `wp04` 保留原指纹格式；混合源中出现反演 schema/主体时默认路径在创建目标前拒绝，不隐式降级。历史保留归档、失败目标、身份及指纹不改写、不接管、不删除。

新配置固定现有 3822 集群标识、父库和反演 sidecar；只增加已有 reader/operator 凭据解析，不新增角色、凭据、迁移或配置路径。源端先检查角色归属/非提权/无成员关系、实际权限、完整迁移与支持对象边界；反演三主体仅接受父库 owner 授予的 CONNECT、无 grant option。未知应用 schema、public 用户对象及未支持对象类型均拒绝。

恢复时表权限沿用既有有效 ACL 比较，保留 owner、grantor、权限及 grant option。PostgreSQL 的 SQL NULL 默认 owner 权限与显式 owner-all 权限可等价；显式空 ACL 不等价，PUBLIC/运行角色授权变化仍拒绝。新 relation_properties 只增加持久性、RLS/forceRLS 和 replica identity 检查，不重复比较表 ACL 的存储表示；schema/列/函数 ACL 与原三库安全观察器不变。

同一只读快照记录 waveform、registry、inversion 全部受支持表的有序内容（含结果 BYTEA）及原生定义、owner、列/表/函数 ACL。新版本独立配置绑定文件（不含凭据）绑定运行、归档哈希和源指纹，目标连接及监督导出子进程重新验证；不改旧 v1 目标身份。恢复后再次校验 schema 和 reader/operator 有效权限，导出阶段只允许 waveform audit/business_audit/capacity 的精确差异，反演内容与目标安全目录须不变。

测试的非空反演结果由真实 HTTP 与生产 worker factory 的新进程产生；新目标上的敏感性检查只在事务/保存点内改变真实结果字节、目录及授权，逐项回滚并比较完整指纹。该检查与原三测试库的外部安全基线分开报告。PostgreSQL 单事务 restore 不包含此前创建目标和授权；失败目标及归档仍保留供诊断。此项仅证明指定软件测试配置，不证明生产备份、PITR、现场精度或一般 PostgreSQL 灾备。
