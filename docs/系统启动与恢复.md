# 系统启动、备份与恢复

## 运行环境

- Windows 10/11，Python 3.11 或更高版本（当前电脑已具备）。
- Edge 或 Chrome 浏览器。
- 平台后端、SQLite 数据库、采集模拟器和前端均在本机运行，不需要 MySQL、Redis、Node.js 服务或外网。
- 业务数据库：`data/platform.db`；运行日志：`logs/runtime.log`；备份目录：`backups/`。

## 正常启动与停止

双击 `start-platform.cmd`，或在项目目录执行：

```powershell
python server.py --launch --open
```

停止：

```powershell
python server.py --stop
```

服务采用操作系统级单实例锁、随机关闭令牌和健康等待机制。启动器只有在 `/api/health` 返回成功后才打开浏览器；停止命令只会关闭本项目持有令牌的实例。

## 在线备份

平台运行中也可以双击 `backup-platform.cmd`，或执行：

```powershell
python server.py --backup
```

SQLite 在线备份先写临时文件，执行完整性与外键检查后原子替换为 `backups/platform-年月日-时分秒-微秒.db`，默认只保留最近 10 份。命令输出中的 `ok` 必须为 `true`、`integrity` 必须为 `ok`。

## 从备份恢复

1. 先执行 `python server.py --stop`。
2. 在 `backups` 中选择已确认时间的备份文件。
3. 执行以下命令，把文件名替换为实际名称：

```powershell
python server.py --restore "backups\platform-20260911-090000-000000.db"
```

4. 恢复命令会先自动备份当前数据库，再校验来源文件、原子恢复并重新执行完整性检查。
5. 执行 `python server.py --launch --open`，打开策略中心和审计日志确认关键记录。

服务仍在运行时，恢复命令会拒绝执行，避免覆盖正在写入的数据库。

## 四类现场故障演练与处置

### 1. 重复启动或端口占用

现象：启动窗口显示“platform already running”或健康等待失败。先访问 `http://127.0.0.1:8765/` 判断现有实例是否正常；正常则继续使用。异常时执行停止命令，查看 `logs/runtime.log`，确认原实例结束后再启动。不要在任务管理器中同时保留两个 Python 平台进程。

### 2. 页面打不开或停留在旧界面

先执行 `python server.py --launch` 检查返回码，再访问 `/api/health`。健康正常时使用 `Ctrl+F5` 强制刷新或重新打开浏览器标签；健康异常则查运行日志。平台静态资源使用 `no-cache`，刷新后应加载当前版本。

### 3. 备份损坏或选错文件

恢复过程在写入现场数据库前检查 `PRAGMA integrity_check` 和外键；损坏文件会被拒绝。选择另一份时间更早的备份重试。不要复制半成品 `.tmp` 或 `.restore` 文件，只选择 `platform-*.db`。

### 4. 操作后数据状态不符合预期

先不要手工修改数据库。记录页面对象编号和时间，到“审计日志”核对状态迁移；执行 `python acceptance_smoke.py` 区分程序故障与现场数据问题。需要回退时先做一次在线备份，再停止服务并按上节恢复。恢复后检查生效策略、签名指令五阶段回执和审计数量。

## 验收前恢复检查清单

- `python acceptance_smoke.py` 返回 0，报告包含 10 个 passed 阶段。
- `python server.py --backup` 返回 `ok: true`。
- 启动、登录、CSV 导出在断网状态正常。
- 重启后 `ES-CONTROL-001` 仍为生效状态，`CMD-CONTROL-001` 仍为成功且保留五阶段回执。
- “系统运行”显示服务和数据库为 `ok`；“验收中心”显示六项能力均有业务证据。
