## 启动顺序

1. 启动认证 Mosquitto broker。
2. 启动中心入库消费者：

   ```powershell
   .\.venv\Scripts\python.exe -m backend.center --config config\center.local.toml
   ```

3. 确认现场 Modbus TCP/RTU 地址和点表后启动边缘网关：

   ```powershell
   .\.venv\Scripts\python.exe -m backend.gateway --config config\gateway.local.toml
   ```

网关断线时消息保存在 `data/uplink-spool.db`。遥测使用 QoS 1 且不保留；只有 broker 返回成功 PUBACK 后边缘队列才确认消息，`No matching subscribers` 也会被视为未完成应用交付。中心消费者使用稳定 Client ID 和 7 天持久会话，离线期间由开启持久化的 broker 排队；消费者使用手动 ACK，只有 PostgreSQL 事务提交或确认同一消息已经幂等入库后才向 broker 确认。

## PostgreSQL 数据结构

- `ingest_messages`：以 `message_id` 为主键保存原始 JSON、SHA-256、主题和序号区间。
- `telemetry_samples`：按 `measured_at` 月份做 RANGE 分区，当前已建立 61 个月分区。
- 同一 `message_id`、同一载荷的重投返回幂等成功；复用同一 ID 发送不同载荷会报冲突。
- 入库账户不拥有建表权限；分区由迁移账户预先创建。

## 平台中心查询（2026-09-23）

双击 `start-platform.cmd` 时优先使用项目 `.venv`；存在 `config/center.local.toml` 时自动启用中心查询。手动启动：

```powershell
.\.venv\Scripts\python.exe server.py --launch --center-config config\center.local.toml
```

不传 `--center-config` 且不设置 `PLATFORM_CENTER_CONFIG` 时，继续以原有本机模式运行。配置错误会阻止启动；数据库暂不可用不会阻止原有业务页面使用，中心区域显示不可用。

- 页面入口：采集监控 → 采集实况，上方为 PostgreSQL 中心记录，下方为本机终端联调记录；数据质量页也显示中心链路统计。
- 支持网关、终端、测点、质量码和时间筛选；默认近 24 小时、单次最多 31 天；每页 100 条，翻页会暂停自动刷新。
- 中心指标按近 24 小时**接收时间**统计，历史测点按**测量时间**查询；改变历史筛选不改变上方当前链路状态。
- “中心可查询”仅表示数据库读通，不代表 MQTT 消费者、网关或物理设备在线。设备从未上报时不会出现在“已接收链路”表；注册台账将在后续模块提供。
- 没有近期上报时显示真实的离线/空值，不拿本机联调记录替代中心记录。
- 查询事务强制只读，单条语句超时 3 秒、锁等待 1 秒、连接超时 3 秒；这些不是整次 HTTP 请求的总超时。
- 可在配置中添加 `[postgres_query]`，使用独立只读身份。未配置时复用 `[postgres]` 凭据，但仍强制只读事务。当前机器尚未部署独立 `oilwell_reader` 账号；正式部署应由数据库管理员创建 SELECT-only 账号后替换。
- 启动会校验既有数据，冷启动允许最多 60 秒；不跳过完整性/清单校验。

本次功能、测试和未完成项详见 `中心遥测查询交付记录-20260923.md`。

## 设备开放接入与中心恢复（2026-09-23）

采集实况页右上角“设备开放接入”打开本机 `/assets/open-interface/index.html`，厂家可下载 OWP-EDGE/1.0 接口标准、JSON Schema、协议测试向量、独立离线校验器、R1 系统/端子参考 SVG 和说明。资料无需登录，不含本机配置或真实凭据；业务数据和管理接口的权限不变。当前只在本机提供页面，没有发布到互联网。

开放资料与已实现接口范围以该目录 INTERFACE.md 为准。ROADMAP.md 是未实现草案，不能按其中 v2 主题接入现有消费者；硬件图不是可制造的元件级原理图，不得直接接动力线或执行机构。

中心消费者增加外层会话监督：首次连接失败、入库错误触发断开、订阅被拒绝等场景结束当前会话后，以 1、2、4、8、16、30 秒上限退避重连；连接存续至少 60 秒后重置外层退避。Paho 内部网络重连另使用 1—30 秒退避。仍复用 client_id 和持久会话，数据库提交前不确认。

关键日志：

- `mqtt_subscribe_requested`：已请求订阅，不代表 Broker 已接受。
- `mqtt_subscribed`：收到匹配 SUBACK 并确认授予 QoS 1。
- `mqtt_subscribe_rejected` / `mqtt_connection_rejected`：权限或会话协商失败；应检查 Broker 配置，不可降低认证要求绕过。
- `ingest_failed`：仅输出异常类型和消息标识，不记录可能含凭据的异常正文。
- `mqtt_retry_scheduled`：外层重连退避秒数；Paho 内部重连不一定产生此事件，不能据此推算全部重连次数。

不要仅凭进程存在或数据库可查询判定采集健康，应同时核对最近订阅成功、新消息接收时间及设备上报状态。持续重复的同一失败可能是永久非法报文或 message_id 冲突；当前缺少持久隔离队列，不能无限留给自动重试处理。还需补齐 SUBACK 等待超时、写入语句/网络卡死截止时间、异常隔离和运维告警。该修正不等于完整端到端可靠性已经达标。

当前消费者日志为 `logs/center-recovery-20260923.stdout.log` / `.stderr.log`。本次只替换中心消费者进程，不重启 PostgreSQL、项目 Broker 或平台网页服务，不启动未知地址的 Modbus 设备。详见 `开放设备接口与采集恢复交付记录-20260923.md`。

Windows 启动脚本现在转发显式命令行参数，例如 `start-platform.cmd --port 8876`；无参数仍使用原默认端口。自动化测试使用独立数据库/日志目录和 `--port 0` 申请临时端口，避免与用户运行中的 8765 端口冲突；单实例锁与停止令牌机制不变。

## 已实跑证据

- Modbus TCP 03/04 功能码读取、`float32` 与缩放 `uint16` 解码通过。
- 认证 MQTT QoS 1 上行通过，匿名连接被拒绝。
- ACL 拒绝发布时可识别负向 PUBACK，消息仍留在边缘队列重试。
- 中心手动 ACK、PostgreSQL 入库和同消息重投去重通过。
- 中心停止期间 broker 持久化排队，中心恢复后消息自动入库通过。
- 完整链路入库值为有功功率 `5.80 kW`、转速 `1234.50 rpm`，写入 `telemetry_samples_y2026m09`。

## 接现场设备前必须补齐

- 厂商 Modbus 寄存器表、设备地址、串口或网络参数。
- CT/PT 变比、功率正负方向、编码类型、字节序和工程量上下限。
- 现场网络地址、中心域名和 CA/客户端证书。
- 本地急停、接触器反馈、门禁/检修状态等硬联锁接口。
- 至少一批同步电参数、载荷位移与人工标注工况，用于反演模型标定和独立验证。
