## 启动顺序

1. 启动认证 Mosquitto broker。
2. 启动中心入库消费者：

   ```powershell
   .\.venv\Scripts\python.exe -m backend.center --config config\center.local.toml
   ```

3. 确认现场 Modbus TCP/RTU 地址和点表后启动边缘网关：

   ```powershell
   .\.venv\Scripts\python.exe -m backend.gateway --config config\gateway.local.toml
   ```

网关断线时消息保存在 `data/uplink-spool.db`。遥测使用 QoS 1 且不保留；只有 broker 返回成功 PUBACK 后边缘队列才确认消息，`No matching subscribers` 也会被视为未完成应用交付。中心消费者使用稳定 Client ID 和 7 天持久会话，离线期间由开启持久化的 broker 排队；消费者使用手动 ACK，只有 PostgreSQL 事务提交或确认同一消息已经幂等入库后才向 broker 确认。

## PostgreSQL 数据结构

- `ingest_messages`：以 `message_id` 为主键保存原始 JSON、SHA-256、主题和序号区间。
- `telemetry_samples`：按 `measured_at` 月份做 RANGE 分区，当前已建立 61 个月分区。
- 同一 `message_id`、同一载荷的重投返回幂等成功；复用同一 ID 发送不同载荷会报冲突。
- 入库账户不拥有建表权限；分区由迁移账户预先创建。

## 已实跑证据

- Modbus TCP 03/04 功能码读取、`float32` 与缩放 `uint16` 解码通过。
- 认证 MQTT QoS 1 上行通过，匿名连接被拒绝。
- ACL 拒绝发布时可识别负向 PUBACK，消息仍留在边缘队列重试。
- 中心手动 ACK、PostgreSQL 入库和同消息重投去重通过。
- 中心停止期间 broker 持久化排队，中心恢复后消息自动入库通过。
- 完整链路入库值为有功功率 `5.80 kW`、转速 `1234.50 rpm`，写入 `telemetry_samples_y2026m09`。

## 接现场设备前必须补齐

- 厂商 Modbus 寄存器表、设备地址、串口或网络参数。
- CT/PT 变比、功率正负方向、编码类型、字节序和工程量上下限。
- 现场网络地址、中心域名和 CA/客户端证书。
- 本地急停、接触器反馈、门禁/检修状态等硬联锁接口。
- 至少一批同步电参数、载荷位移与人工标注工况，用于反演模型标定和独立验证。
