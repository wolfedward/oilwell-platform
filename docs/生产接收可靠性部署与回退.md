# 生产接收可靠性：部署、检查与回退

WP-03 响应 Y1-02（可靠数字采集与处理）和 Y1-03（安全传输与共享）。代码在独立工作区实施，`deployed=false`。本文件是受控部署操作依据，不是已经投产、现场效果或设备安全认证的证明。冻结演示版及现有服务不参与迁移。

## 状态的准确含义

网关 application 模式保留报文精确字节，Broker 发布确认不能使记录完成；必须收到并在本地持久保存与该报文匹配的中心应用回执。应用回执可能先于 Broker 发布确认到达，不要求两者固定顺序，晚到的发布确认不能逆转最终状态。`stored` 表示中心已保存报文和测点；`quarantined` 表示中心已持久隔离，未转为有效测点。原始事实与应用回执不因人工关单而改变。关闭后同一异常再次出现可重新打开案件。

发送器的 `broker_confirmed` 只说明 Broker 已接收回执，不证明网关已在本地完成确认。网关自身的最终状态才是该端证据。旧队列的 Broker 确认保留为 `legacy_broker_confirmed`，不能改名冒充应用确认。无法可靠识别主题和三项身份的异常只保留原文，不臆造回执。

合法但未登记、质量坏或点表不符的遥测仍保存原始报文与测点，由台账核查单独给出原因；不把“设备未知”当成报文丢弃理由。本功能不下发设备控制，不计算现场算法准确率或节能率。

## 身份分离与部署前提

必须由获授权管理员确认目标服务器/库名、备份、存储余量及回退窗口，另行授权生产迁移。不能将测试初始化程序用于业务库，不能提升已有入库账号权限。

| 身份 | 配置段 | 允许用途 |
| --- | --- | --- |
| 可靠入库 | `postgres_reliable_ingest` | 原报文、测点、隔离事实及首次回执的事务写入 |
| 回执发送 | `postgres_receipt_publisher` | 租约领取、发送状态与健康信息；无台账或人工案件管理权 |
| 异常只读 | `postgres_ingest_reader` | 固定元数据视图；不能直接读取原始字节或测点表 |
| 异常操作 | `postgres_ingest_operator` | 授权的人工案件操作、审计及受限原文访问 |
| 独立迁移 | 单独迁移配置 | 显式 DDL 和最小授权，不作为服务运行账号 |

所有声明的可靠接收身份及既有 `postgres` 段指向完全一致的 host/port/database，用户名不同。台账 `postgres_registry` / `postgres_query` 保持其独立身份，不复用异常元数据只读账号。运行身份不能持有数据库/schema/表所有权、超级用户或间接越权权限；启动只读预检发现不符即拒绝，不自动修复授权或迁移结构。

密码只通过环境变量或系统凭据引用；不得写入源码、日志或公开厂家包。远程 PostgreSQL 使用 `verify-full` 和可信 CA，远程 MQTT 使用可信 CA 和正常主机名校验；本机隔离试验的无 TLS 回环配置不能搬到外网。正式 Web 使用 HTTPS，Origin 为精确允许列表，不信任 Host 推导授权。

## 显式迁移及配置

迁移模块 `backend.ingest_reliability.migrate` 提供显式 Python 接口 `migrate(settings, expected_database=..., limits=CapacityLimits(...))` 和 `grant_roles(connection, roles={ingestor: ..., publisher: ..., reader: ..., operator: ...})`，不是命令行入口。部署管理员须用已核实的独立迁移连接调用，完成后在运行账号上执行下面的只读检查；不能拿 `tools/provision_ingest_test.py` 代替生产迁移。001—003 为已记录摘要的顺序迁移，不能编辑旧迁移掩盖结构不匹配。与本系统既有中心表配合使用；迁移不创建业务数据库或用户。备份必须覆盖原始中心表、新 schema、审计和应用配置；备份存在不等于恢复演练成功。

从 `config/center.example.toml` 配置 `reliability.enabled`、两级逻辑原文字节限额、明确的 `receipt_gateways`、运行身份及允许来源。默认不启用应用回执，空网关允许列表不发送。参数容量应与已迁移数据库一致，不得通过运行时配置偷偷扩容。

中心和独立发送器分别只读检查，再受控启动：

```powershell
.venv/Scripts/python.exe -m backend.center --config config/center.local.toml --check
.venv/Scripts/python.exe -m backend.ingest_reliability --config config/center.local.toml --check
.venv/Scripts/python.exe -m backend.ingest_reliability --config config/center.local.toml --once
```

`--check` 不接 MQTT，不证明网络、ACL、现场连接或数据流已正常。`--once` 才尝试一个有界回执批次，失败返回非零；常驻发送器不加这两个参数。先启动可验证的接收与回执服务，再逐个网关启用 application 模式，不能同时切换所有设备。

MQTT 身份分离：网关只写自身遥测主题、只读自身回执主题；中心只读遥测；发送器只写回执。参考 `config/mosquitto.acl.example`、`config/mosquitto.example.conf`，替换示例网关身份并逐项核验，不授予通配全写。Broker 的 payload 限额和完整 MQTT packet 限额不同，完整 packet 包含主题与属性。当前模板均为 2 MiB，但边界 2 MiB payload 加头会触发 packet 拒绝；合法遥测上限仍是 1 MiB，回执上限 4 KiB。

本机 Mosquitto 2.1.2 / Paho 2.1.0 的较低 payload 限额实验观测到 MQTT 5 PUBACK `0x95`；该组合客户端不接受此 PUBACK reason。不要在不了解 Broker/SDK 版本行为时独立调低 payload 限额。正式版本组合及 ACL/限额必须重新实测，厂家资料说明相同边界。

## 网关队列切换与应用确认检查

停掉该网关自己的采集/上传进程，确认队列不被占用，记录原路径和摘要。用 `backend.gateway.spool_migrate --help` 所示参数显式初始化新队列，或指定一个尚不存在的备份路径迁移旧队列。迁移前核对剩余磁盘、条数/字节配额，迁移失败保留原队列和备份；不由服务启动自动迁移。备份不能与队列或 WAL/SHM 路径相同。

逐网关检查：身份及前缀一致；MQTT QoS 1、非 retained；回执订阅成功；应用确认明确启用；稳定 client_id；队列 v2；中心网关允许列表；实际读写 ACL；遥测及回执 SHA-256 是原始字节，不是重新序列化 JSON。使用一个唯一软件验证报文检查网关 awaiting_receipt → stored、中心单条报文/测点/事实及一致回执。不把此报文混入现场生产统计。

数据库不可用、事务失败、容量不足时不向网关发出虚假的 stored。断线/重启后仍用原 message_id、主题和字节重试。更正错误数据必须使用新的报文编号，不以复用编号覆盖旧事实。

## 监控、人工处置与保留

页面入口为“接收异常与回执”。基本查看、原文读取、人工管理、审计查看分别受权限约束，权限撤销后旧幂等操作也不能绕过检查。预览/下载先提交访问审计，原文按文本显示；下载仍应由接收者自行验证 SHA-256。页面不会把 503 当成无异常或空列表。

监控未关案件数及最老年龄、隔离增量、待发回执及最老年龄、最近失败码、发送器心跳、逻辑容量、网关队列余量及真实磁盘。逻辑原文字节不包含索引、数据库日志、WAL、备份等开销；已确认网关记录也保留，不自动删除以腾出空间。到容量限额必须保全证据并按审批保留策略扩容/归档，不能静默丢弃旧数据。

人工写操作携带版本和幂等键。网络中断或 5xx 后在当前工作区保留相同正文及键，切换记录/筛选再返回仍可恢复原操作重试；409 先重新读取再确认新操作；401/403 先核查登录/权限。不将原因或未决请求写入浏览器持久存储，关闭工作区、刷新整页或重新登录后须先查结果和审计，不承诺跨会话自动恢复。补发只改变回执投递安排，不修改固定回执，不宣称网关已经收到。关闭案件不删除原文、不自动重新导入隔离数据。

## 回退

1. 先停止此次新启用的接收/回执/网关进程，记录队列、未决消息和服务身份，保留数据库/schema、审计、原始字节及全部新队列文件。
2. 按受控变更关闭 `reliability.enabled`，恢复已核实的原中心配置；原链路只在既有权限下工作，不增加旧账号权限。
3. **旧程序不能打开 v2 队列。** 不改 schema version、不覆盖旧备份、不把已确认或隔离状态改成 Broker 成功。需要旧链路时使用已核实的独立旧队列路径；所有停机期间/新路径未决记录须单独核对，不能声称透明无损降级。
4. 灾难恢复由管理员在独立恢复目标验证备份，再决定切换；应用不删库、不删 schema 或不可变事实以“恢复运行”。本包没有自动灾备承诺。
