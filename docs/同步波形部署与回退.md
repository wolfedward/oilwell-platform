## 变更前记录与隔离

1. 由授权管理员记录目标主机、实例、库名、数据库版本、schema/迁移版本、独立身份、应用代码版本、配置摘要、已存在服务、备份位置及恢复窗口。核对真实目标库身份后做覆盖旧中心原文、新波形 schema、审计、队列、配置与凭据引用的**一致备份**，并在独立恢复目标验证。不得把测试重置脚本用于业务库，也不得自动把演示库记录迁为生产测量。
2. 检查 PostgreSQL 18、`btree_gist` 1.8 位于 `public`，精确原生函数清单 212 个签名（其中 7 个列定布尔支持函数 parallel-unsafe、205 个 safe），以及扩展 owner 为可信 registry owner、superuser 或成员 owner 为 superuser。版本、schema、定义或 owner 不合支持清单时停下做兼容审查；启动不会修扩展、改 owner 或自动授权。此固定检查不能防御恶意数据库 superuser 或操作系统库替换。
3. 保持 **registry schema owner 与 waveform schema owner 两类 owner 彼此分离**；波形离线迁移以 waveform owner 身份执行，不另造第三个 schema owner。owner/迁移身份与波形 receiver/assembler/reader/operator 等运行身份分离；运行账号不持有 schema/表所有权、超级用户或可达升级权限。按实际链 `001_capture.sql` → `002_import_sessions.sql` → `003_evidence.sql` → `004_datasets.sql` → `005_portable_structure.sql` 显式核对版本与不可变源码摘要、先做只读检查，再由获准的 owner/迁移身份执行所需升级和既有离线角色 grant；不修改已应用迁移以掩盖不匹配。005 只追加结构指纹元数据：先验证原001—004摘要及v4旧结构指纹，再追加v5按 schema/表/索引限定名称排序的可移植结构指纹，避免恢复后内部索引 OID 顺序差异；不覆写历史、业务数据、结构定义或权限，owner/ACL仍独立核查。Web/worker 启动只做只读预检，缺结构、权限、身份或有效持久配置就返回 unavailable，不执行 DDL、不提升业务账号。台账与波形要协调更新：最终 registry 事务先拿中性历史锁的 EXCLUSIVE 后锁 head，波形质量/配对/数据集在业务 guard 后、payer/capture 前拿 SHARED。旧版或临时脚本不合作时，此锁不能保护它们；只读启动也无法证明它们不存在。必须登记并停止/更新这些写者后才可切换。
4. 同库历史投影由不同 owner 以离线固定列授权，波形 reader 只读五个固定投影，无 registry 原表写权。波形 reader 的离线列授权还精确包含 `waveforms.imports(import_id,file_sha256,file_bytes,line_count,final_lf)`、`waveforms.state_head(singleton,version)` 和 `waveforms.streams(capture_pk,stream_id,chunk_count)`；无 tablewide/raw/operator 权限扩张。`imports` 五列是后续有意新增 ACL，不能声称最终 ACL 与旧 003 完全一致。逐账号用真实有效权限探测，任何不足或意外扩权均停止。运行时不自动 grant。
5. 在已配置网关额度中**显式**选择并持久绑定 `shared_accounting_bucket`，为共享证据、附件、数据集保留 metadata/attachment 余量；它是计费 sponsor，不证明设备物理来源。没有首网关自动选择或上线时重新分配。其饱和可同时阻塞业务操作和自身接收。核对每网关独立持久 MQTT 会话/额度、总配置覆盖额度之和；单 manifest 预占 32 MiB，封存释放未用部分，单事实最低 1 KiB。逻辑额度之外还要量测数据库/WAL/索引/备份、sender 文件/rollback journal 和磁盘真实余量，设置告警与保留策略；限额不是测得吞吐。
6. 分离每网关发布、中心接收和回执发布身份，实际测试只允许本网关 `{prefix}/v2/{gateway_id}/{device_id}/waveform` 上行和对应 `waveform-ack` 读取/写入方向，QoS 1、非 retained；不得授予通配全写。远程 PostgreSQL 使用 `verify-full` 与可信 CA，MQTT 使用受信 CA/正常主机名核验，页面/API 使用 HTTPS、精确 Origin、有效认证和当前岗位权限。隔离回环测试配置不复用于外网。密钥只走私密引用，不入代码、日志或公开包。先用少量明确 synthetic 唯一身份核对原字节、摘要、回执与隔离路径，随后逐网关受控启用；不得把软件向量计为现场产量。

## 运行监测与证据边界

`--check` 及 Web readiness 为只读依赖/结构/权限检查，不连接实物、不代替网络 ACL、TLS、备份恢复或旧写者审计。所有 durable 写入在事务内要求 `fsync=on`、`full_page_writes=on` 和有效 `synchronous_commit=on` 或 `remote_apply`，检查 logged 关系，且**提交之后**才返回成功；不通过启动或故障注入去关闭共享集群设置。已覆盖的配置持久提交/进程崩溃实验不构成物理断电认证。事务提交失败或结果不确定不得返回成功；台账暂不可用不阻止合法原始证据保存，但会影响业务准入。

当前 API 适配仍基于 Python 3.13 的 `http.server`；[官方文档](https://docs.python.org/3.13/library/http.server.html) 明确不把它作为生产 Web 承载。Task13 的本机 HTTP/浏览器通过仅验证现有适配行为。正式暴露前仍需单独选择并验证受支持且已修补的运行时、加固的 HTTP 承载与 TLS 边缘、受限请求并发和全局资源上限、停止/取消/恢复及实际部署兼容性；仅加反向代理或单次 socket 超时都不能证明这些条件已满足。此次未替换服务器框架或完成生产联调。

监测各网关会话、原文事实/隔离、缺片、24 h `stalled`、30 s 可续租 assembly lease、每 token 累计最多 5 min、待发回执/最老年龄、quota/磁盘、历史锁和 503 原因。UTC 回退会持久记录告警、失效当前装配租约并暂停新领取，直至数据库 UTC 追上非递减 high-water；进程内单调时钟不持久化，检查间不可观测的跳变不能保证被发现。`stalled` 不自动删片，迟到原片仍可完成。接收/装配停止用单一 20 s 优雅期限：先停新工作，尝试支持的有界查询取消，再确认实际 worker/连接退出。取消函数返回不等于服务端查询已经停止；`shutdown_incomplete` 只允许 supervisor 对**该确切自有进程**升级处置，同时保留耐久 lease/receipt 供恢复。不得批量杀 Python、数据库或 Broker 服务。

线上 manifest 的最终 MQTT ACK 回答已登记的在线请求；离线导入只有 HTTP 保存/完成状态，无自动 MQTT 回执。混合传输可补精确缺字节；离线完成后重发同一 manifest 才登记在线请求并从原完成事实产生最终回执。不能凭自报 `source_kind`、导入方式或仅片到达推断物理来源。`stored` 是原报文保存，`quarantined` 是隔离，`complete` 是收齐封存，`invalid` 是终局无效；complete 不是质量合格。来源证据、中心配置 UUID/SHA 与厂家可空标签、中心校准 ID/SHA/通道绑定、UTC/误差/时基、独立物理周期、当前限制均分别判断。配对两侧可指向同一联合评估，绝非两次独立测量；历史评估归属和时间只是当时快照，不等于当前井绑定或准入。管理分页 token 绑定资源/目标/筛选/page_size/时间边界及活数据修订，原样带回；换范围或 409 后从第一页重启。它不是签名授权，也非永久快照。

定量同步准入需把受控来源和同步报告连起来核验：每个实际采集流须核对 capture 的 gateway/device/boot、stream、clock domain、原采样计数器、参考样本索引和同一物理触发事件；索引落在原 manifest 支持区间，名义参考 ns 用原 offset、索引和精确有理采样率算出。独立批准的同步记录需要解释计数器/事件对应的非空说明，至少一份受控接线/时序或已核验映射报告附件，并由审核人判断其是否支持斜率、事件、适用窗口及误差界。程序的一致性检查、相同标签或 UTC 声明都不能代替该报告或证明现场实测。不同 capture 的事件要用各自 UTC 起点平移，缺必要起点/不确定度则待证；UTC 不确定度只用于绝对锚点一致性，不自动算入相对同步预算。

误差账本要写清归属：端点 offset/residual/频漂是相对参考时钟的差分界，共同绝对时钟偏差不重复计；同一已核验流端点可供其通道共享映射，但不算两份独立端点误差，各通道校准 residual 仍分别保留。参考端点已知 offset/frequency 为零，null 表未知，触发 residual 可以非零。频漂从证据参考时刻到所选支持区间最远端累计，包含参考到周期起点的年龄，不能在周期起点归零；有效名义区间不外推，证据/历史限制按校正后的物理支持另行核对。前端/导出保留精确坐标：wire 绝对样本序号与 ns 是规范 i64 整数字符串；派生 API `relative_ns` 可为规范约分后的 `分子/分母`，例如 `1000000000/3` ns，而不是把 wire 改成分数。分组、配对、区间比较用精确有理数；两位小数仅供图表显示，不回写原文或推断独立物理周期。

数据集每次成员编辑最多 100、每版本最多 1000；物理周期/派生变体不跨分区复用。原始档案/证据与定量用途分开，`qualified_collection` 不等于独立验证。导出意图 `research/training/evidence` 与数据集 `raw_archive/software_pair_test/field_pair_input` 是不同字段；冻结 manifest 与规范文件字节保持历史不变，当前限制单独展示，**每次**下载/重试重查限制和权限，成功审计提交先于首字节。已经发送的字节不能撤回。大 manifest 按有界块传输，不是普通 JSON。原 `.owpwave`、原 capture 报文和规范导出摘要各自保留；规范化末行 LF 会使导出哈希可能不同于原文件。附件仅 PDF/PNG/JPEG、每件最多 4 MiB、每记录最多 8 件；不自动取外部 URL、不执行上传内容。

单 capture 上限（16 MiB 解码、32 MiB 原始报文、512 片、8 流/32 通道、60 s、1—128000 S/s）必须同时满足。`frame_bytes=5×channels`；128000 S/s 的 32 通道 16 MiB 例只有 104857 整帧/16777120 字节、首末 0.8191875 s，6 通道则 559240 帧/16777200 字节、4.3690546875 s。它们只是分配算例，既不是现场采样建议，也不能把必要物理周期截短以通过。质量算法按完整解码 capture 限额执行；每通道 20000 原始预览帧是**显示**上限，不是质量输入上限。Task17 已取得下述分段隔离测量，不能从格式限额或有限实测推断生产产能。

本地 sender 仅验证 Windows 固定本地 NTFS；其他系统/文件系统、网络或设备路径、硬链接别名拒绝。一个 spool 只绑定一个网关，init/enqueue/run/status 共用排他所有权，run 占用时其他命令返回 busy。`charged_bytes` 是逻辑计费，不等于 SQLite 数据库、journal 或备份的物理磁盘大小。新 sender 用 SQLite `journal_mode=DELETE`、`synchronous=EXTRA`、已拥有的新库 guard；不迁移旧标量队列、不手动删 sidecar/hot journal。当前验证栈 Python 3.13.2/SQLite 3.45.3、paho-mqtt 2.1.0，私有 Paho socket 清理依赖需在升级时复核。SQLite 官方 [WAL 文档 §11](https://www.sqlite.org/wal.html) 记载该版本相关的多连接 checkpoint/write 风险；[同步设置说明](https://www.sqlite.org/pragma.html#pragma_synchronous) 支撑新 sender 的 DELETE+EXTRA 选择。这不表示旧队列/运行时已修补，进程崩溃恢复也非物理断电验证。逻辑归档与诊断有界，停收后重试/未决会积累，应监控而非删除。

## 停收、回退与重新启用

先记录精确新 worker PID、配置、会话、事实/回执水位、队列文件摘要及积压。停止**仅此次新启用的**接收、装配、sender/回执 worker，或在受控重启中设 `waveforms.enabled=false`；完成上述优雅退出核验。保留所有原文事实、slot、审计、出站回执、lease、spool、导入会话、历史证据及 schema，不 DROP、不重写原文、不把旧队列当新队列打开。积压期间的容量和重试告警持续保留；需要恢复时先修依赖/权限、核对历史锁合作写者和额度，再逐网关恢复，按原身份/字节重放，不能重用 capture_id 覆盖不同内容。灾难恢复只能用经验证的备份在独立目标演练后经批准切换。本文没有完成正式迁移、现场 TLS 链路、实物同步/标定、生产最大吞吐、断电或生产恢复演练的声明。
